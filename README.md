# شركة بابل للتوظيف — Babylonian Recruitment Company (BRC)

منصة توظيف كاملة **تعمل بالكامل في المتصفح** (HTML + CSS + JavaScript) بلا خادم وبلا إنترنت،
مبنية على هوية بابلية: **بوابة عشتار** في الواجهة و**أسد بابل** رمزاً للقوة والالتزام.

> **جاهز للاستخدام فوراً:** افتح `index.html` أو استعمل الملف المستقل:
> • `brc-standalone.html` — **النسخة الكاملة** بجودة صور عالية (2.6 ميجا).
> • `brc-light.html` — **نسخة خفيفة** بنفس كل شيء وصور مضغوطة (≈1 ميجا) تفتح وتُعرض بسرعة، مناسبة للواتساب والإيميل.
>
> كلاهما ملف واحد يحتوي الصور وخطوط Cairo والكود — احفظه وأرسله ويعمل بلا إنترنت.

## 1) ما الذي بُني؟

### أ) الموقع العام للزبائن والباحثين عن عمل — `index.html`
- **واجهة (Hero)** بخلفية بوابة عشتار + بطاقة أسد بابل الذهبية، وإحصاءات حيّة من قاعدة البيانات.
- **بحث سريع بالكود المصغّر** `BRC-1042` + بحث بالاسم/المنطقة/الدوام/الحالة بفلترة فورية.
- **بطاقات وظائف** تعرض: الكود، العنوان، المنطقة، الأجر، الدوام، الحالة — **وبلا أي بيانات لصاحب العمل**.
- **نافذة تفاصيل الوظيفة** مع تنبيه صريح بسياسة الخصوصية وآلية الحجز 24 ساعة.
- **الحجز والتواصل**: زر «احجز» في كل بطاقة وظيفة يفتح واتساب الشركة (07760058007) برسالة جاهزة تحمل كود الوظيفة؛ والحجز يتم في المكتب بالحضور أو بالاتصال.
- **مصدر البيانات مع السحابة المفعّلة:** الوظائف المعروضة تُقرأ من واجهة `brc.public_jobs` في قاعدة
  الشركة **فقط** — يظهر هيكل تحميل (skeleton) أثناء القراءة، ولا يظهر للزائر أي بيانات تجريبية
  أو كاش متصفح إطلاقاً. إن كانت القاعدة بلا وظائف معلنة: «لا توجد وظائف معروضة حالياً»، وإن فشل
  الاتصال: «تعذّر الاتصال بقاعدة الشركة» مع زر إعادة المحاولة — ولا نسقوط للبيانات المحلية.
- أقسام: آلية العمل (5 خطوات يبدأها تواصل الباحث) · الخدمات · عن الشركة مع أسد بابل · الحجز والتحقق · شريط اقتباس · تواصل.
- **الصلاحيات:** الزائر **يتصفّح فقط** — لا يقدّم طلب استمارة ولا يتحقق من أي استمارة. إصدار الاستمارات والتحقق منها **للموظفين والإدارة فقط** عبر المنظومة الداخلية، وبوابة دخولهم زر ظاهر في ترويسة الموقع.

### ب) صفحة التحقق — أداة داخلية للموظفين والإدارة — `verify.html`
بوابة صلاحية أولاً: بلا جلسة موظف فعّالة لا تُعرض أي بيانات (ولا حتى وجود الرقم من عدمه)، ويظهر بدلها
تنبيه «التحقق خاص بموظفي الشركة والإدارة» مع مسار دخول الموظفين ودعوة الزائر للتواصل للحجز.
بجلسة موظف، `verify.html?form=BRC-NO-000120&t=<بصمة>` تُظهر:
- حالة الاستمارة: **سارية / منتهية الصلاحية (30 يوماً) / استُهلكت المحاولات / مكتملة (توظيف ناجح)**.
- بيانات الباحث + المحاولات الخمس مع **أكواد الوظائف** (`BRC-1042`) وحالة كل مهلة وملاحظاتها.
- تحذير أمني إن كانت بصمة الرابط غير مطابقة (مؤشر تلاعب).
- كيو آر كود التحقق + طباعة نسخة من الاستمارة.

### ج) المنظومة الداخلية للموظفين والإدارة — `dashboard.html`
- **الدخول:** عبر Supabase Auth حصراً (`enforceAuth: true` — لا كلمات مرور في الكود). الدور
  (مدير عام / موظف توظيف) وصلاحياته من سطر الموظف في جدول `brc.staff`. البوابة ظاهرة للموظفين
  عبر زر «دخول الموظفين» في ترويسة الموقع العام.
- **نظرة عامة:** إحصاءات + «إجراءات مطلوبة الآن» (حجوزات قاربت الانتهاء، استمارات منتهية، محاولات مستهلكة، مرشحون مرفوضون) + آخر العمليات.
- **إدارة الوظائف:** إضافة/تعديل/إغلاق/إعادة تفعيل/حذف + ترشيح مباشر + بيانات صاحب العمل الداخلية.
- **الباحثون والاستمارات:** إصدار استمارة، إدارة المحاولات الخمس، طباعة الاستمارة A4، تسجيل الرسم، رابط التحقق.
- **متابعة الحجوزات (24 ساعة):** عدّاد تنازلي لكل حجز + تثبيت النتيجة (نجاح/رفض) + إفراج فوري + قائمة «انتهت المهلة».
- **سجل التدقيق اللحظي:** كل عملية بالثانية `YYYY-MM-DD HH:mm:ss` مع المستخدم، الصلاحية، IP الجلسة، العملية، والتفاصيل + تصدير CSV.
- **اللوحة المالية (للمدير):** عدد الاستمارات الصادرة ومحاولات الطباعة و**التحصيل المتوقع لكل موظف** والمستلَم فعلياً وعدد التوظيف الناجح + رسم بياني بالأعمدة.
- **الإعدادات:** عدد المحاولات، مدة الصلاحية، مدة الحجز، رسم الاستمارة، تشغيل/إيقاف الإفراج التلقائي + نسخ احتياطي JSON (تصدير/استيراد) + إعادة ضبط.
- **النسخ الاحتياطي المجدول (أسبوعي مرن):** نسخة سريعة بزر واحد · نافذة جدولة باختيار أي أيام من الأسبوع ووقت التنفيذ · محرّك تلقائي يُنشئ **نسخة واحدة لكل (يوم + وقت)** ويلتقط النسخة الفائتة في نفس اليوم لو فُتحت الصفحة متأخرة · زر «نفّذ نسخة الآن» · قائمة النسخ مع الحجم والتصدير والاستعادة والحذف · نطاق مخصص بالتاريخ (نسخة جزئية تُدمَج عند الاستعادة بدل أن تستبدل) · يُحتفظ بآخر 20 نسخة مع إسقاط الأقدم تلقائياً إذا امتلأت مساحة المتصفح.

## 2) دليل التشغيل

```bash
# 1) معاينة محلية (خادم بسيط بلا حزم تشغيلية)
npm start                      # ثم افتح http://localhost:4173
#    - الموقع العام      : /
#    - صفحة التحقق       : /verify.html?form=BRC-NO-000120
#    - لوحة الموظفين     : /dashboard.html
#    - الملف المستقل      : /brc-standalone.html

# 2) أو بلا أي أدوات: افتح الملفات مباشرة بالمتصفح
#    index.html · verify.html · dashboard.html · brc-standalone.html
```

### النشر — Cloudflare Pages فقط (مربوط بـ Git)
المنصّة المعتمدة للنشر هي **Cloudflare Pages** (أُزيل إعداد Render و `render.yaml` من المستودع):

- **المشروع مربوط بـ Git (Connect to Git):** كل دفعة إلى `main` تُبنى وتُنشر **تلقائياً** على
  `https://babylonian-recruitment-company.pages.dev` — وكل PR يحصل على رابط معاينة. لا حاجة إلى
  مفاتيح API ولا `.github/workflows` ولا رفع يدوي (وإضافة workflow مع الربط القائم تعني نشرين
  لنفس الموقع — لا تفعل).
- **البناء:** لا شيء (موقع ثابت — الملفات المبنية مودَعة في Git) — Production branch: `main` ·
  Build command: فارغ · Output directory: `.`.
- **الترويسات والمسارات النظيفة:** `_headers` و `_redirects` في الجذر يقرأهما Cloudflare تلقائياً
  (بديل حرفي لِما كان في `render.yaml`): ترويسات أمنية، منع تخزين `sw.js`، وكاش طويل للأصول،
  وإعادة كتابة `/verify` · `/dashboard` · `/standalone` · `/light`، وتحويل مسارات الأقسام
  (`/jobs` · `/services` · `/how` · `/about` · `/contact`) إلى مراسيها في الصفحة الرئيسية.
- **النطاق الرسمي:** `brc-babil.com` **غير مسجَّل بعد** (استعلام DNS يرجع NXDOMAIN) — لا تعتمد عليه
  كرابط حي ولا تطبع استمارات عليه قبل تسجيله وربطه في Custom domains. الرابط الحي الفعلي هو
  نطاق `pages.dev` أعلاه، وهو نفسه رابط الكيو آر الاحتياطي في `config.js` (`verifyBase`).
- **رفع يدوي للطوارئ فقط:** `npm run dist` يبني `dist/` (ملفات الموقع فقط بلا أدوات/اختبارات)
  يُرفع عبر Create deployment في لوحة Cloudflare — استثنائي، فالأصل هو النشر الآلي من Git.
- **بعد كل تحديث واجهة:** `npm run build && npm run build:light` ثم ارفع `CACHE_NAME` في `sw.js`
  (الحالية: `brc-cache-v5`).

📄 **الخطوات الكاملة + إلغاء Render + قائمة فحص بعد النشر:** `docs/deploy-cloudflare.md`

### الحفظ والنقل
- **ملف واحد:** `brc-standalone.html` (≈ 2.6 ميجابايت) — انسخه على فلاش/هاتف/إيميل، افتحه بأي متصفح،
  ويعمل **بلا إنترنت**: الصور والخطوط والكود كلها داخله. مساراته: `#home` `#jobs` `#!verify?form=...` `#!dashboard`.
- **مجلد المشروع:** انسخ المجلد كاملاً (يعمل بفتح `index.html` مباشرة أيضًا — كل المسارات نسبية).

### الحسابات والدخول
- **لا حسابات في الكود إطلاقاً:** `assets/js/config.js` يحمل `users: []` — الباب الخلفي
  (كلمات مرور منشورة في الواجهة) مُغلق نهائياً.
- **الدخول عبر Supabase Auth حصراً:** `enforceAuth: true` في `assets/js/supabase-config.js`،
  والدور والصلاحيات من جدول `brc.staff` وسياسات RLS (انظر `docs/schema.sql` و
  `docs/binding-status.md` لإنشاء حساب موظف وربطه).
- **بوابة الموظفين ظاهرة في الموقع العام:** زر «دخول الموظفين» في ترويسة الصفحة الرئيسية
  يفتح `dashboard.html` (وفي النسخة المستقلة يفتح المسار الداخلي `#!dashboard`) — الدخول
  نقرة واحدة طبيعية، لا ضغط مطوّل ولا إيماءات مخفية.
- **النسخة المستقلة (`brc-standalone.html`)** للعرض والمشاركة بلا إنترنت — لوحة الموظفين فيها
  تحتاج القاعدة السحابية، فاعتمدها لعرض الموقع العام فقط.

## 3) قواعد العمل المطبّقة (مطابقة للمواصفات)

| القاعدة | التفصيل | مكان التنفيذ |
|---|---|---|
| **كود مصغّر لكل وظيفة** | `BRC-####` فريد يُولَّد تلقائياً | `BRCStore.nextJobCode()` |
| **استمارة 30 يوماً** | رقم تسلسلي `BRC-NO-000120`، تاريخ إصدار وانتهاء، وتحوّل تلقائي إلى «منتهية» | `createApplicant` + `runMaintenance` |
| **5 محاولات** | كل استمارة فيها 5 خانات، تُستخدم بالترتيب ولا تُعاد المحاولة المرفوضة | `trg`/`activeAttempt` |
| **حجز 24 ساعة** | عند الاختيار → الوظيفة «محجوزة مؤقتاً» + مهلة 24 ساعة وعدّاد تنازلي | `selectAttempt` |
| **الإفراج التلقائي** | انتهاء المهلة ⇒ الوظيفة «متاحة» + وسْم المحاولة «انتهت المهلة / تتطلب إجراء» + سجل | `runMaintenance` (كل 30 ثانية + عند التحميل) |
| **إعادة تفعيل الفرص** | رفض المرشح ⇒ الوظيفة «متاحة» فوراً + تفعيل المحاولة التالية تلقائياً | `setOutcome('rejected')` |
| **الخصوصية** | اسم/هاتف/عنوان صاحب العمل ومكان المقابلة **لا تُعرض في الموقع العام** — تُسلَّم عبر الشركة وبها في الاستمارة المطبوعة | `public.html` + `listJobs` |
| **التدقيق** | كل عملية بالثانية مع المستخدم و IP والتفاصيل | `audit()` |

## 4) الاستمارة المطبوعة A4 + الكيو آر كود

- **الترويسة:** شعار BRC + الاسم العربي/الإنجليزي + «شركة بابل للتوظيف (شركة الهدف)»
  + أرقام الهاتف `07760058007` / `07863148999` + العنوان «حلة - شارع 60 - قرب مستشفى الكفل - مجاور الجيلاوي».
- **صندوق بيانات الباحث:** الرقم التسلسلي `BRC-NO: 000120`، الاسم، الهاتف، العنوان، تاريخ الميلاد،
  الجنسية، تاريخ الإصدار، تاريخ الانتهاء، مدة الصلاحية، عدد المحاولات، الموظف المُصدر.
- **جدول المحاولات الخمس:** المحاولة # | كود الوظيفة | المنطقة | الوظيفة | هاتف جهة الاتصال | صاحب العمل | حالة المهلة | التاريخ.
- **التذييل:** كيو آر كود التحقق + الرقم التسلسلي + التواقيع + ختم الشركة + الإخلاء القانوني نصاً:
  > *«ملاحظات مهمة: خدمات الشركة تنحصر في توفير الأيادي العاملة من الناحية الفنية والتخصصية فقط وليس الأمنية. الشركة غير مسؤولة قانونياً وعشائياً عن الشخص المرسل وصاحب العمل.»*
- **الطباعة:** CSS مخصّص `@media print` بمقاس **A4** — ورقة بيضاء نظيفة بلا أي علامة مائية أو صورة خلفية.

### الكيو آر كود
يحتوي رابط تحقق مشفّر البصمة يتبع نطاق النشر تلقائياً (`autoVerifyBase`) — على الموقع المنشور:
`https://babylonian-recruitment-company.pages.dev/verify?form=BRC-NO-000120&t=<8 hex>`
والاحتياطي المطبوع عند تعذّر ذلك (`verifyBase` في `assets/js/config.js`) هو نطاق Pages الفعلي نفسه
(نطاق `brc-babil.com` غير مسجَّل — انظر أعلاه). في النسخة المحلية يفتح: `verify.html?form=...`.

**المولّد:** تنفيذ مستقل بالكامل في `assets/js/qr.js` (بدون أي مكتبة خارجية — يعمل بلا إنترنت)،

## 5) التحقق الشامل — خمس حزم اختبار

```bash
npm install            # مرة واحدة (jsdom للتطوير فقط)
npm run build          # إعادة بناء الصفحات + الملف المستقل
npm test               # ① اختبارات سلوكية شاملة (jsdom)
npm run test:backup    # ② النسخ الاحتياطي والجدولة (عبر HTTP لأن localStorage يحتاج أصلاً حقيقياً)
npm run e2e            # ③ المسار الكامل من الزائر إلى التحقق والطباعة
npm run audit          # ④ تدقيق جودة المشروع (ترابط، تنسيق، إتاحة، طباعة)
npm run verify:qr      # ⑤ تقرير مولّد الكيو آر كود
npm run verify:qr:full # ⑥ مطابقة مرجعية + فك ترميز فعلي
npm run test:all       # كل ما سبق دفعة واحدة
```

### آخر إصلاحات التحقق (كلها مُختبرة)
- ✅ **«صفحة غير موجودة» عند النقر على الوظائف/خدماتنا/آلية العمل واسم الشركة**: روابط الترويسة
  والتذييل مكتوبة في القوالب بالشكل `index.html#jobs` (وهو الشكل الوحيد الذي يعمل أيضاً عند فتح
  الملفات من القرص وفي اختبارات jsdom)، لكن على الاستضافة قد لا يكون اسم الملف قابلاً للطلب
  مباشرةً — فتُعطي النقرة صفحة مفقودة رغم أن القسم في نفس الصفحة. أُضيف `assets/js/nav.js`
  يُطبّع كل رابط وقت التشغيل: مرساة خالصة (`#jobs`) داخل الصفحة الرئيسية، ومجلد الصفحة + المرساة
  (`/#jobs`) من صفحتي التحقق واللوحة، ويبقى `index.html#jobs` كما هو على `file://`، ويتنحّى
  تماماً في الملف المستقل (راوتر `#!` صاحب القرار هناك). ويضيف تمريراً سلساً يخصم ارتفاع الترويسة
  اللاصقة حتى لا يختفي عنوان القسم تحتها.
- ✅ **صفحة 404 بهوية الشركة** (`404.html` تُبنى من `src/partials/notfound.html`): أي رابط قديم أو
  مطبوع بخطأ يبقى داخل الموقع مع ترويسة الشركة وتذييلها وروابط كل الأقسام وزر واتساب، بدل صفحة
  بيضاء من المضيف. مراجعها مثبّتة على جذر الموقع لأنها تُخدَم على عنوان المسار الأصلي.
- ✅ **مسارات الأقسام النظيفة**: `/jobs` · `/services` · `/how` · `/about` · `/contact` تُحوَّل (301)
  إلى مراسيها، و`/index.html` إلى الجذر — في `_redirects` وفي خادم المعاينة `tools/serve.mjs` معاً.
- ✅ **عامل الخدمة كان يُبقي أجهزة على نسخة قديمة**: `cache.addAll` يسقط كاملاً لو تعذّر ملف واحد،
  فيبقى المتصفح على كاش الجيل السابق. صار كل ملف يُضاف على حدة، وارتفع الجيل إلى `brc-cache-v5`،
  وأُضيف `nav.js` و`404.html` إلى الكاش مع احتياط تنقّل لا يُظهر شاشة خطأ عارية.
- ✅ **أزرار النسخ الاحتياطي والجدولة كانت لا تعمل إطلاقاً**: كتلة «النسخ الاحتياطي المجدول» في `assets/js/store.js` كانت موضوعة **بعد قوس إغلاق الوحدة (IIFE)**، فكانت `nowISO/db/save/emit/audit` خارج النطاق ويرمي المتصفح `ReferenceError` بصمت عند كل نقرة. نُقلت الكتلة داخل الوحدة وأُضيفت دوال جدولة موحّدة (`getAutoSchedule/saveAutoSchedule/clearAutoSchedule/checkAutoBackup`).
- ✅ **نافذة التأكيد كانت ترجع «إلغاء» دائماً**: في `UI.confirm` كان `close()` يستدعي `onClose → resolve(false)` قبل `resolve(true)`، فتتعطل كل العمليات المؤكَّدة (حذف نسخة، إيقاف جدولة، إعادة ضبط، حذف وظيفة). أُضيف علم «استقرّ الوعد» وتُحلّ النتيجة قبل الإغلاق.
- ✅ **عدّادات لوحة الإعدادات لم تتغير أبداً**: `renderSettings()` كانت تكتب `.value` على عناصر `<div>`؛ الآن تكتب `textContent` لغير حقول الإدخال، فتظهر أعداد الوظائف والاستمارات والسجلات والنسخ.
- ✅ **الجدولة التلقائية لم تكن تُنفَّذ عملياً**: المؤقّت القديم في `dashboard.js` كان يشترط أن تكون الساعة ضمن ±5 دقائق من الوقت المحدّد (فلا يلتقط نسخة إذا فُتحت الصفحة بعدها) ويترك مفتاحاً يومياً يتراكم في المتصفح. حُلّ بمحرّك واحد في المتجر + تنظيف المفاتيح القديمة.
- ✅ **الربط المكرّر/الضائع للأزرار**: دالة `bindOnce()` تربط كل زر مرة واحدة فقط، وتُستدعى من `bindActions()` ومن `renderSettings()` معاً — فالأزرار تبقى تعمل بعد أي إعادة رسم ولا تُنفَّذ مرتين.
- ✅ **حماية مساحة التخزين**: حدّ 20 نسخة + إسقاط الأقدم وإعادة المحاولة عند `QuotaExceededError` بدل فشل صامت، مع رسالة خطأ واضحة في الواجهة.
- ✅ **أيقونة `i-close` غير المعرّفة** في زر «إيقاف الجدولة» استُبدلت بـ `i-x` الموجودة في الـ sprite.
- ✅ **قاعدة حجم أساسية للأيقونات**: كانت 274 أيقونة `class="ic"` بلا حجم افتراضي، وكانت ستُرسم بحجم افتراضي ضخم في المتصفح.
- ✅ **سجل التدقيق بالتوقيت المحلي**: كان يعرض UTC خاماً؛ الآن بصيغة `YYYY-MM-DD HH:mm:ss` بالتوقيت المحلي (وتصدير CSV مثله).
- ✅ **خانات المحاولات لا تُعاد**: المرفوضة/المنتهية تبقى في تاريخ الاستمارة، والحد الأقصى 5 مفروض فعلياً.
- ✅ **حالة الحجز متناسقة** مع البيانات التجريبية (حجوزات جارية حقيقية بعدّاد 24 ساعة).
- ✅ **تناسق العدّادات**: لا تصادم في الأرقام التسلسلية عند الإصدار الجديد.
- ✅ **ترقيم ديناميكي في النوافذ**: كل معرّف يستدعيه الكود موجود (ثابت أو مبني في النافذة) — 154 معرّفاً في الملف المستقل.

## 8) الترقية إلى السحابة (اختياري)

المنطق الموجود في `store.js` منقول حرفياً إلى قاعدة بيانات جاهزة في **`docs/schema.sql`**:

- **جداول:** `staff` · `jobs` · `applicants` · `job_attempts` · `audit_log` · `settings`
  (مع توليد `BRC-####` و`BRC-NO-######` من تسلسلات، وضمان 5 خانات لكل استمارة).
- **مشغّلات:** حجز 24 ساعة + منع الحجز المزدوج + إعادة الوظيفة عند الرفض + إغلاقها عند النجاح + تدقيق تلقائي بالفروق (jsonb).
- **إفراج تلقائي مجدول:** `brc.run_auto_release()` مع `pg_cron` كل دقيقة (حجوزات + انتهاء استمارات + استهلاك محاولات).
- **RLS:** الزائر يقرأ `brc.public_jobs` (بلا بيانات صاحب العمل) فقط، ويعمل التحقق عبر `brc.verify_form(serial, token)`،
  والموظف يدير، والمدير وحده يرى المالية وسجل التدقيق الكامل، وسجل التدقيق غير قابل للتعديل أو الحذف.
- **دوال RPC:** `brc.select_attempt` · `brc.set_outcome` · `brc.release_hold` · `brc.verify_form`.
- **واجهات جاهزة:** `brc.v_financials_by_staff` (اللوحة المالية) و`brc.v_pending_actions` (إجراءات مطلوبة) وRealtime.

خطوات الربط: أنشئ مشروع Supabase → SQL Editor → الصق `docs/schema.sql` → Run،
ثم استبدل دوال `BRCStore` بنداءات `supabase-js` (نفس أسماء الدوال والبنية) — الواجهة لا تحتاج أي تغيير.

## 9) ملاحظات وحدود النسخة الحالية

- البيانات تُخزَّن في **localStorage** داخل المتصفح (لكل متصفح بياناته). زر «إعادة ضبط» يعيد البيانات التجريبية،
  والتصدير/الاستيراد ينقل البيانات بين الأجهزة.
- **IP** المسجّل في سجل التدقيق هو معرّف الجلسة المحلية (لا يوجد خادم) — في النسخة السحابية يُسجَّل IP الحقيقي من ترويسات الطلب.
- **البصمة** (`t=`) المطبوعة في الكيو آر كود هي بصمة تحقق داخلية للنسخة المحلية؛ في الإنتاج تُستبدل بتوقيع HMAC من الخادم
  (الدالة `brc.verify_token` جاهزة في المخطط).
- التحقق من التزوير في النسخة المحلية محدود (لا خادم مركزي)؛ الأمان الكامل يأتي مع النسخة السحابية.
- الصور المُستخدمة توضيحية/فنية للهوية البصرية البابلية، والخط **Cairo** بترخيص OFL (انسخ ترخيصه مع الخط عند النشر).
