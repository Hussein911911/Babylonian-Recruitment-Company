# عرض تدريجي للوظائف — «عرض المزيد / عرض أقل»

**الهدف:** لوحة «أحدث الوظائف» في الموقع العام تعرض **أول 10 وظائف فقط** عند الفتح،
بدل سرد كل الوظائف دفعة واحدة. زر **«عرض المزيد»** يُظهر بقية النتائج، ثم يتحوّل
نفس الزر إلى **«عرض أقل»** فيُعيد أول 10.

## السلوك

| الحالة | المعروض | الزر |
| --- | --- | --- |
| فتح الصفحة / بعد أي تغيير فلتر | أول 10 من النتائج المطابقة | «عرض المزيد» + ملاحظة «تعرض 10 من 20 وظيفة» |
| ضغط «عرض المزيد» أو «عرض الكل» في رأس القسم | كل النتائج المطابقة | «عرض أقل» + ملاحظة «تعرض الآن كل النتائج: 20 وظيفة» |
| ضغط «عرض أقل» | أول 10، مع التمرير إلى أعلى الشبكة | «عرض المزيد» |
| نتائج ≤ 10، أو لا نتائج، أو هيكل تحميل، أو فشل الاتصال | كل النتائج (أو رسالة الحالة) | **مخفي** تماماً |

- **العدّاد** `#jobs-count` يعرض دائماً **عدد النتائج الكلي بعد الفلاتر** لا عدد
  البطاقات المعروضة؛ وملاحظة ``#jobs-more-note`` تشرح المعروض منه (ذات `aria-live="polite"`).
- **الفلاتر** (بحث، محافظة، دوام، حالة، تخصص، شرائح التصفية النشطة، البحث السريع،
  مسح QR) تُعيد القائمة إلى الطيّ تلقائياً عبر بصمة الفلاتر في `renderJobs()`،
  فلا يبقى الزائر أمام توسيع لا يناسب بحثه الجديد. **تحديث البيانات وحده**
  (Realtime / الصيانة الدورية) لا يطوي قائمة موسّعة اختارها الزائر.
- **الترتيب** لا يتغيّر: التوسيع يضيف البطاقات التالية بعد أول 10، وترقيم
  البطاقات يبدأ من 1 في الحالتين. لا تغيير في `Store.listJobs` ولا في استعلام
  القاعدة، ولا تخزين لحالة العرض في `localStorage`.
- **إتاحة الوصول:** زر `type="button"` بـ `aria-expanded` و`aria-controls="jobs-grid"`،
  ملاحظة حيّة للقارئات، إطار تركيز واضح، واحترام `prefers-reduced-motion` عند
  التمرير. الزر خارج `#jobs-grid` كي لا يفقد تركيزه عند إعادة رسم البطاقات.
- **رأس القسم:** «عرض الكل» كان مرساةً إلى نفس القسم بلا أثر، فصار زراً يُظهر
  كل النتائج وينتقل إلى الشبكة؛ ويُخفى حين تكون كل النتائج ظاهرة فعلاً.
- **وضع القاعدة:** أثناء الـ skeleton وعند «تعذّر الاتصال بقاعدة الشركة»
  يُخفى زر العرض التدريجي، فلا يظهر إلا مع قائمة وظائف حقيقية.

## الملفات

- `src/partials/public.html` — عناصر الزر والملاحظة (المصدر الوحيد للـ HTML).
- `assets/js/public.js` — `JOBS_PAGE_SIZE = 10`، حالة العرض، بصمة الفلاتر،
  `renderJobsMore()` / `hideJobsMore()` والمعالجات.
- `assets/css/app-shell.css` — تنسيق الزر، إخفاء `[hidden]`، دوران أيقونة «+»
  إلى «×» عند «عرض أقل».
- `index.html` و `hrc-standalone.html` و `hrc-light.html` — **ملفات مبنية**
  من `node tools/build.mjs` و `node tools/build.mjs --light`؛ لا تُعدَّل يدوياً.
  تغيّر بصمة الأصول `?v=` في بقية الصفحات تلقائياً مع أي تعديل على JS/CSS.
- `sw.js` — رُفع `CACHE_NAME` إلى `hrc-cache-v152` وفق سياسة المشروع، كي لا
  يحتفظ زائر قديم بنسخة مخزَّنة من الصفحة أو `public.js`.

## المعاينة المحلية

```bash
npm start                 # ثم افتح /demo — 20 وظيفة وهمية بلا إنترنت ولا مفاتيح
                          # (أو افتح / لقراءة الوظائف الحقيقية من Supabase)
```

المسار `/demo` في `tools/serve.mjs` يحقن البذرة الوهمية في الذاكرة عند الطلب فقط؛
لا تُكتب في ملف، ولا تُنسخ إلى مجلد النشر، ولا تصل للإنتاج.

## التحقق

```bash
npm run test:jobs-show-more     # 37 فحصاً: jsdom + سكربتات الصفحة الفعلية، بذرة 22 وظيفة وهمية، بلا شبكة
npm test                        # الدخان الشامل (140 فحصاً)
npm run test:job-filters        # فلاتر صفحة التقديم (لا تتأثر)
```

فحص الأداء `tests/performance-smooth-browser.mjs` (120 وظيفة وهمية) صار يضغط
«عرض المزيد» قبل قياس التمرير، لأن العرض الابتدائي أصبح 10 بطاقات.

> اختبارات محلية ببيانات وهمية؛ لا ترحيل قاعدة بيانات ولا تغيير في صلاحياتها
> ولا في واجهة `brc.public_jobs` لهذه الميزة.
