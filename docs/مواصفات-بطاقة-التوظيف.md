## 3) النموذج الجديد — الرحلة الكاملة

1. **الإصدار**: المدير يولّد **دفعة بطاقات** من اللوحة؛ لكل بطاقة **باركود فريد (QR)** + **رمز خاص لكل فرصة من فرصتيها**؛ تُسجَّل الدفعة باسم نقطة بيع معينة.
2. **البيع والتخصيص (بنقطة البيع)**: الزبون يدفع **كاشاً**؛ مشغّل نقطة البيع يقرأ الباركود بأي موبايل، يعبّي بيانات الزبون (نفس حقول الاستمارة الحالية عدا الدفع)، ويختار له الوظيفة الأولى؛ التقديم يُسجَّل فوراً (الفرصة 1) و**تُطبع البطاقة** بحجم البطاقة المصرفية وتُسلَّم له.
3. **الحجز**: الوظيفة تصبح **محجوزة 24 ساعة** (مقفلة عن بقية الزبائن).
4. **القرار**: صاحب العمل يبلّغ الشركة → الموظف يسجّل: **تم التوظيف** أو **رفض**.
5. **انتهاء 24 ساعة بلا قرار**: الوظيفة تنتقل إلى حالة **«حرجة»** — لا إفراج تلقائي — بانتظار قرار الموظف: **تم التوظيف / إرجاعها متوفرة / حذفها**.
6. **الفرصة الثانية**: يقدّم بها الزبون إمّا عند نقطة البيع، أو **بنفسه أونلاين**: يدخل باركود بطاقته بالموقع → يختار الوظيفة → يُثبت الرمز الخاص بالفرصة → **يطبع ورقته الجديدة من أي مكتب استنساخ** (صفحة «بطاقتي» فيها زر طباعة).
7. **الانتهاء**: استنفاد الفرصتين (رفضاً أو توظيفاً) → البطاقة **منتهية**؛ يريد المحاولة فيشتري بطاقة جديدة ويعبّي معلوماته من جديد.

### الأدوار

| الدور | شنو يسوي |
|---|---|
| **المدير العام** | تسعير البطاقات (متغيّر)، إصدار الدفعات وإسنادها لنقاط البيع، إدارة الموظفين ونقاط البيع، التقارير والمالية |
| **موظف التوظيف** | إدارة الوظائف، تثبيت القرارات (توظيف/رفض) بعد إشعار صاحب العمل، معالجة **قائمة الحالات الحرجة** |
| **نقطة البيع (مكتب استنساخ)** | بيع البطاقة كاشاً، تعبئة بيانات الزبون، اختيار الوظيفة، طباعة البطاقة، إضافة الوظيفة الثانية للزبون |
| **الزبون** | **بدون حساب** — عبر الباركود: متابعة حالته، إضافة الوظيفة الثانية بنفسه، إعادة طبع ورقته |
| **صاحب العمل** | خارج النظام — يبلغ الشركة هاتفياً والموظف من يغيّر الحالة |

> **ملاحظة أمان (قرارك):** الباركود **مكشوف** — من يملك الورقة يملك التحكم. الحماية الإضافية الاختيارية في §10-5.

## 5) الفرصتان والرموز

- **مستقلتان تماماً**: يقدّم للأولى وينتظر ثم يستخدم الثانية عند الرفض، **أو** يقدّم لوظيفتين بنفس الوقت.
- لكل فرصة **رمز خاص** مطبوع على البطاقة.
- **التقديم الذاتي أونلاين** يتطلب: الباركود + الرمز الخاص بالفرصة المستخدمة.
- **التقديم عند نقطة البيع**: الباركود يكفي (النقطة مخوّلة وتعبّي بدال الزبون).
- تُستهلك الفرصة بـ: **توظيف** أو **رفض**. 🔶 مصيرها عند «الإرجاع/الحذف» بعد الحرجة = قرار 1.
- يبقى المنع القائم: لا تُستهلك الفرصتان على **نفس الوظيفة**.

## 6) الحالات وقاعدة الـ24 ساعة

### الوظيفة
```
متوفرة ──(تقديم زبون)──▶ محجوزة (24 ساعة، مقفلة عن غيره)
محجوزة ──(قرار الموظف بعد إشعار صاحب العمل)──▶ مكتملة (توظيف ✓) أو متوفرة (رفض، ترجع للغير)
محجوزة ──(مرور 24 ساعة بلا قرار)──▶ حرجة ⏳
حرجة ──(قرار الموظف)──▶ مكتملة (توظيف) / متوفرة (إرجاع) / محذوفة
```

### البطاقة
```
مصدّرة (بنقطة البيع) ──بيع + بيانات زبون──▶ نشطة (فرصتان) ──استنفاد الفرصتين──▶ منتهية
```
🔶 هل التوظيف ينهي البطاقة فوراً حتى مع بقاء فرصة؟ = قرار 2.

### التقديم (فرصة الزبون)
| الحالة | المعنى |
|---|---|
| **معلّق** | مقدَّم والوظيفة محجوزة له، بانتظار القرار |
| **موظَّف** | قُبل — تم التوظيف |
| **مرفوض** | رفض بقرار الموظف بعد إشعار صاحب العمل |
| **منتهٍ بانتظار قرار** | الوظيفة صارت حرجة — مصير التقديم بيد الموظف |

**العدّاد سيرفري**: يُدار من القاعدة (`pg_cron` + احتساب زمني عند القراءة) — يعمل حتى لو لم يفتح أحد الموقع.

## 8) التسعير والدفع

- **الدفع كاش حصراً** عند نقطة البيع وقت شراء البطاقة — لا فيزا، لا ماستر كارد، لا أي بوابة إلكترونية.
- **السعر متغيّر**: يحدده المدير من الإعدادات (نفس آلية «رسم الاستمارة» الحالية، تتحول إلى «سعر البطاقة») ويسري على نقاط البيع، مع **سجل تسعير** بالتدقيق.
- تُسجَّل قيمة البيع الفعلية مع كل بطاقة (للتقارير المالية ومحاسبة النقاط).

## 9) تغييرات قاعدة البيانات (على السكيما الحقيقية `brc`)

| التغيير | التفصيل |
|---|---|
| **جديد: نقاط البيع** | جدول `brc.points_of_sale` (الاسم، العنوان، الهاتف، فعّالة/موقوفة) + حسابات دخول بصلاحية «نقطة بيع» + سياسات RLS: **ترى بطاقاتها فقط** |
| **جديد: الدفعات** | جدول دفعات الإصدار (المدير، عدد البطاقات، نقطة البيع المستلِمة، التاريخ) |
| **تطوير الاستمارة → البطاقة** | البطاقة = سجل الباحث الحالي + **باركود فريد** + **رمز لكل فرصة** + نقطة البيع البائعة + سعر البيع الفعلي |
| **الفرص** | البطاقات الجديدة تُخلق بفرصتين (`trg_make_attempts` تعدَّل) 🔶 والاستمارات القديمة بخمس محاولات تكمل بنظامها (قرار 5) |
| **الحرجة بدل الإفراج التلقائي** | إيقاف `run_auto_release` للبطاقات؛ الوظيفة بعد 24 ساعة تنتظر قرار الموظف (توظيف/إرجاع/حذف) |
| **الإعدادات** | «رسم الاستمارة» → «سعر البطاقة» (متغيّر من المدير) |
| **التدقيق** | كل عمليات البيع والتخصيص والطبع وقرارات الحرجة تدخل سجل التدقيق اللحظي الموجود |

## 10) الأمان

1. **RLS كما هو**: الزائر يرى الوظائف العامة فقط؛ نقطة البيع ترى بطاقاتها؛ الموظف يدير؛ المدير يرى المالية.
2. **بصمة رابط التحقق** (موجودة) تبقى لروابط التحقق.
3. **سجل التدقيق اللحظي** (موجود) يغطي كل جديد.
4. **المفاتيح السرية** تبقى خارج الكود (كما هو الحاصل اليوم).
5. 🔶 **حماية إضافية اختيارية**: عند التقديم الذاتي أونلاين نطلب **رقم هاتف الزبون المسجَّل بالبطاقة** يطابق (بلا SMS، مجاناً) — تحمي الزبون إذا ضاعت ورقته أو انسرقت. اقتراحنا: نعم.
