# نسختك الاحتياطية — مراجعة كاملة وتجربة فعلية

> راجعنا الحلقة من أولها لآخرها، وشفنا **ثلاثة أعطال حقيقية**.
> هذا الملف يقول شنو تغيّر، وشلون تنزّل، وشلون تجرّب.

---

## ما تغيّر اليوم — ثلاثة أعطال

### ١) زر تنزيل الهيكل كان يعطي ملفاً ناقصاً

**قبل:** ملف واحد **٣١٥٤ سطراً**. محرّر Supabase يقصّ عند ~٢٠٠٠ **ويرفع Success**.
**بعد:** **٥ أجزاء** (٦٩٩ · ٦١٧ · ٦٩٧ · ٦٦٥ · ٤٧٤) — كلها تُلصق.

**الأثر عليك:** لو ما انتبهنا، كنت تبني قاعدة فيها **١١ جدولاً من ١٩**

### ٢) الموقع كان يطلب النسخة القديمة

**قبل:** `recovery_export_v2` — لا تصدّر **٤ جداول**.
**بعد:** `v3` أولاً، ثم `v2`، ثم `v1`.

**الأثر عليك:** **٤٦ فرصة مستهلكة** على **٣٠ بطاقة** كانت ترجع متاحة ← العميل
يعيد استخدام فرصة **دفع ثمنها**.

### ٣) الاسترجاع كان يفشل على أول صف

**قبل:** `v3` تُصدّر `code_hash` وهو **سرّي** — أو تُسقطه فيفشل الإدخال.
**بعد:** لا يُصدَّر، ويُكتب بديل حتمي غير سرّي عند الاسترجاع.

**الأثر عليك:** **كل استرجاع يفشل قبل أن يبدأ** — بخطأ `23502`.

## كيف تنزّل النسخة — ٤ خطوات

```
١. ادخل الموقع بحساب المدير
٢. لوحة التحكم → النسخة الاحتياطية
٣. اختر كلمة مرور قوية (١٠ أحرف على الأقل) — واحفظها في مكان منفصل
٤. اضغط «تنزيل» ← يوصلك ملف hrc-backup-YYYY-MM-DD-HHmm.hrcbak
```

**ثم:** انقله إلى `D:\HRC-Backups` على USB أو اللابتوب.

**⚠️ كلمة المرور لا تُخزَّن في أي مكان.** لو نسيتها، الملف لا يُفتح — أبداً.

**⚠️ التنسيق:** `hrc-backup-2026-11-15-2300.hrcbak` — التاريخ والوقت داخل الاسم.
احتفظ بآخر ٣، واحذف الأقدم (أو اتركها — الملف ~١ م.ب فقط).

## كيف تجرّبها — على مشروع Supabase جديد

### ⓪ قبل أي شي

| ما تحتاجه | من أين |
|---|---|
| مشروع Supabase فاضي | supabase.com — مجاني |
| ملف `.hrcbak` | من الموقع |
| كلمة مروره | من ذاكرتك |
| `restore.html` | من المستودع أو الموقع |

### ① الإضافات

`Database → Extensions`: فعّل **pgcrypto** و **pg_cron**

### ② الهيكل — ٥ لصقات

افتح `restore.html` محلياً → أدخل كلمة المرور → زر **«تنزيل ملفات الهيكل»**
→ يعطيك ٥ ملفات. الصقها بالترتيب في SQL Editor، **استعلام جديد لكل جزء**.

> لماذا لا تُلصق في استعلام واحد؟ لأن المحرّر يقصّ عند ٢٠٠٠ سطر بصمت.
> الأجزاء الخمسة كلها أقل من ٧٠٠ — لا قصّ.

### ③ البيانات

من `restore.html` → زر **«تنزيل 2-data.sql»** → الصقه.
لو الملف كبير: `node tools/split-sql.mjs 2-data.sql --out parts` ثم بالترتيب.

### ④ إصلاح التصدير

الصق `docs/sql-parts/live-2026-11-15/1-إصلاح-تصدير-النسخة.sql` — **٨٩ سطراً**.
بدونه لن تصدّر النسخة من القاعدة الجديدة الفرص المستهلكة.

### ⑤ الإعدادات اليدوية

| ما | أين |
|---|---|
| `app.brc_secret` | Database → Settings → Config (نفس السرّ القديم) |
| المفتاح الجديد | `npm run supabase:repoint <ref> <key>` |
| مخزن `job-images` | Storage → New bucket (public) |
| حسابات الموظفين | Authentication → Add user (٣ أشخاص) |

### ⑥ التحقّق — لا تعتمد على الشعور

شغّل `docs/sql-parts/تحقق-النسخة.sql`:

```
① الأعداد   ← يجب أن تطابق: 724 بطاقة · 1533 محاولة · 3775 تدقيق
② الروابط   ← كل الأرقام صفر
③ الدوال    ← ترجع «أحمد م.» و«0770••••67»
```

**ثم جرّب بنفسك:** امسح باركود بطاقة حقيقية ← يجب أن تُفتح.

## الحقائق المزعجة — بصراحة

| الحقيقة | |
|---|---|
| **كلمات المرور لا تُنقل** | في `auth.users` ولا تُصدَّر (أمنياً صحيح) |
| **`app.brc_secret` لا يُنقل** | سرّ — يُنسخ يدوياً |
| **صور الوظائف لا تُنقل** | ملفات لا SQL — ٤ صور تُرفع |
| **الاختبار على قاعدتي** | ليس دليلاً على قاعدتك |
| **`pg_cron` قد يغيب** | ٤ مهام مجدولة تحتاج تفعيلاً |

**كلها موثّقة — ولا شي منها يفقدك بيانات.**
