# لو انغلقت خدمة Supabase كلها — شنو البديل؟

> سؤال مختلف عن «مشروعي انوقف». هنا: **الشركة نفسها أغلقت أبوابها.**
> لا لوحة، لا دعم، لا مشروع جديد. DNS قد يتوقف. تنتهي الفاتورة ولا أحد يرد.

---

## الجواب المباشر

**الموقع يبقى فاتح — والبيانات تبقى معك — لكن ما يقدر يقرأ ولا يكتب.**

**البديل:** تنقل القاعدة إلى أي PostgreSQL + تبنى ٣ أشياء صغيرة كانت Supabase
تعطيها جاهزة: تسجيل دخول · تخزين صور · واجهة API.

**الجهد: ٢–٤ أيام لمبرمج.** لا شهور. لأن الموقع **ما بُني على Supabase**.

---

## لماذا هذا ممكن أصلاً؟ — لأن موقعك نادر

فحصت الكود. موقعك **لا يعتمد على Supabase** إلا بمقدار رفيع:

| ما نستخدمه | أين | كم سطر |
|---|---|---|
| `from()` — قراءة الجداول | `cloud.js` | ٣ مواضع |
| `rpc()` — نداء دوال | `cloud.js` | ٦ مواضع |
| `signIn` / `getSession` | `cloud.js` | ٧ مواضع |
| `storage.from('job-images')` | `store.js` | ٢ مواضع |
| `channel()` — تحديث لحظي | `cloud.js` | ١ موضع |

**و`assets/js/cloud-http.js` موجود أصلاً** — عميل HTTP بلا أي تبعية (~٢ ك.ب)
يتكلم PostgREST مباشرة. أي أن نصف الطريق مبنيّ من قبل.

**لا يوجد `PostgrestClient` ولا اعتماد على مكتبة Supabase في قراءة البيانات.**
المنطق كله في القاعدة (٦٦ دالة)، والدوال مكتبة SQL قياسية — تعمل في أي
PostgreSQL.

## ما مات مع Supabase — وما بقي

| ما | الحالة | البديل |
|---|---|---|
| **قاعدة PostgreSQL** | ✅ **حية** — هي PostgreSQL عادي | تنتقل كما هي |
| **٦٦ دالة SQL** | ✅ تُنصَّب في أي مكان | لا تغيير |
| **البيانات** | ✅ على USB | تُسترجع |
| **ملفات الموقع** | ✅ Cloudflare Pages | لا تغيير |
| — | — | — |
| **تسجيل الدخول** | ❌ مات | Supabase Auth بديل مفتوح: **GoTrue** |
| **الصور** | ❌ ماتت | أي مخزن: **MinIO** · Cloudflare R2 · مجلد |
| **واجهة API** | ❌ ماتت | **PostgREST** — مفتوح، نفس الشكل تماماً |
| **التحديث اللحظي** | ❌ مات | اختياري — الموقع يعمل بلا Realtime |
| **المجدول** | ❌ مات | `pg_cron` يُركَّب في أي PostgreSQL |

**النقطة الجوهرية:** الثلاثة المفقودة **مفتوحة المصدر ومجانية** — وكانت
Supabase تستعملها هي نفسها. ولذلك الموقع لا يحتاج تعديلاً في المنطق.

## ماذا يعني «الموقع يرجع» — بصدق

### الأسبوع الأول (طوارئ) — يومان

```
① سيرفر PostgreSQL (VPS بـ٥ دولار · أو Neon المجاني)
② تركيب PostgREST + GoTrue + MinIO     ← ساعات، وكلها جاهزة
③ استرجاع السكيما والبيانات            ← ساعة واحدة (مُثبت)
④ تعديل supabase-config.js              ← أمر واحد
⑤ إعادة كلمات المرور لـ٣ أشخاص
⑥ رفع ٤ صور وظائف
```

**بعدها: الموقع يعمل كما كان.** نفس الصفحات، نفس الأزرار، نفس الباركود.

### ما لن يعمل في اليوم الأول

| ما | لماذا | متى يرجع |
|---|---|---|
| التحديث اللحظي بين موظفين | يحتاج Realtime | أسبوع (اختياري) |
| لوحة Supabase للتصفح | راحت | فوراً عبر أي عميل SQL |
| النسخ التلقائي المجاني | راحت | نضبطه عندنا |

**لا شي من هذا يوقف العمل اليومي.**

## الطريق الأسهل — إن أردت بلا سيرفر

| الخيار | PostgreSQL | Auth | Storage | المجموع |
|---|---|---|---|---|
| **Neon + PostgREST** | ✅ مجاني | ⚠️ | ⚠️ | ٢ · ٣ أيام |
| **Railway / Render** | ✅ | ⚠️ | ⚠️ | ٢ أيام |
| **سيرفر VPS عندك** | ✅ | ✅ GoTrue | ✅ MinIO | ٣ أيام |
| **Supabase مُستضاف عندك** | ✅ | ✅ | ✅ | **يوم واحد** ← الأسرع |

**الخيار الأخير:** Supabase نفسها **مفتوحة المصدر** — تُنصَّب على سيرفر
تملكه. فلو أغلقت الشركة، الكود عندك وتشتغل بلا إذن منهم.

---

## لكن — السؤال الذي يجب أن يُسأل أولاً

**هل إغلاق Supabase احتمال حقيقي؟**

| الحقيقة | |
|---|---|
| الشركة | ممولة جيداً، ملايين المستخدمين |
| الإغلاق المفاجئ | **غير مرجّح** |
| إيقاف حسابك أنت | **أرجح بكثير** (فاتورة، مخالفة، تحقق) |
| انقطاع ساعات | **الأرجح** |

**الخطر الحقيقي ليس الشركة — بل حسابك.**

إذاً الاستعداد الصحيح **ليس** بناء بديل كامل. بل:

```
① نسخة على USB                  ← تحميك من كل شيء
② مشروع Supabase احتياطي جاهز    ← ١٥ دقيقة، تحميك من إيقاف حسابك
③ خطة PostgREST موثّقة           ← هذه الصفحة، للاحتمال البعيد
```

## الخلاصة في كلمتين

**لو انغلقت الشركة كلها: الموقع يبقى، البيانات تبقى، والبديل موجود ومفتوح.**

**ولكن ٩٥٪ من المخاطر تحلّها خطوتان لا تكلفان شيئاً: نسخة على USB،
ومشروع احتياطي جاهز.**

**لا تبنِ البديل الكامل قبل أن تحتاجه — لكن اعرف أنه ممكن في يومين.**
