# هل تعمل نسختنا على قاعدة بيانات أخرى؟

## الجواب القصير

**نعم للبيانات. لا للاستخدام اليومي الكامل.** والفرق مهم.

اختبرنا فعلياً على PostgreSQL عادي (بلا Supabase إطلاقاً):

| الخطوة | النتيجة |
|---|---|
| طبقة التوافق (٤٠+ سطر) | ✅ |
| السكيما ٥/٥ | ✅ **١٩ جدولاً · ٦٦ دالة** |
| استرجاع ٧٢٤ بطاقة | ✅ ٧٢٤ بطاقة · ١٤٤٨ محاولة |
| تصدير v3 | ✅ يرجع كل البيانات |

**أي: بياناتك لا تُفقد، ولو أُغلقت Supabase نهائياً.**

## لكن ما لا يعمل

| ما | الحالة | لماذا |
|---|---|---|
| **تسجيل الدخول** | ❌ | Supabase Auth لا بديل له |
| **صور الوظائف** | ❌ | Supabase Storage |
| **الإفراج التلقائي عن الحجوزات** | ❌ | يحتاج pg_cron |
| الموقع نفسه | ⚠️ | يحتاج تعديل `supabase-config.js` |

بدون تسجيل دخول: **لا أحد يقدر يفتح لوحة التحكم**. البيانات موجودة، لكن مغلقة.

## ترتيب اللصق على PostgreSQL عادي

```
① 0-طبقة-التوافق.sql          ← مرة واحدة
② schema/schema-part-01..05   ← بالترتيب
③ 2-data-part-01..NN          ← بالترتيب
④ 1-إصلاح-تصدير-النسخة.sql    ← بعد بيانات v2
```

الطبقة تنشئ: `auth` (جداول + دوال) · الأدوار الأربعة · `extensions` +
`pgcrypto` + بدائلها.

## الصراحة الكاملة: أي سيناريو ينجو؟

| السيناريو | البيانات | الموقع |
|---|---|---|
| Supabase متوقفة ساعات | ✅ في نسختك | ✅ يرجع لما ترجع |
| Supabase أُغلقت نهائياً | ✅ محفوظة | ⚠️ تحتاج سيرفر + نظام دخول |
| انتقلت لـ Supabase آخر | ✅ | ✅ **يرجع كاملاً** |

**السيناريو الوحيد الذي يُرجع الموقع شغّالاً بكامل وظائفه هو مشروع Supabase جديد.**
الترحيل إلى PostgreSQL عادي يحفظ البيانات — لا يُرجع الخدمة.

## ما أوصي به

| # | الإجراء | الغرض |
|---|---|---|
| ١ | مشروع Supabase ثانٍ (تجربة) | تدريب على الاسترجاع بلا مخاطرة |
| ٢ | نسخة أسبوعية على USB | الحماية الحقيقية من إغلاق الحساب |
| ٣ | PostgreSQL محلي (اختياري) | طمأنينة أن البيانات بصيغة مفتوحة |

الثالث ليس ضرورياً. الثاني هو الذي يحميك فعلاً — **النسخة على USB تبقى عندك
حتى لو أُغلق الحساب كله.**
