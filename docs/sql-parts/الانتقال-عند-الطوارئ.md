# الانتقال إلى مشروع Supabase جديد — دليل الطوارئ

> **هذا الدليل مكتوب للحظة الأسوأ:** الموقع واقف أو Supabase أُغلقت، وأنت تحتاج
> موقعاً يعمل خلال ساعات. كل خطوة مُختبرة، وكل تحذير مأخوذ من تجربة فعلية.

---

## ⚠️ أولاً: حقيقة عن الحدّ الذي واجهته

المحرّر عندك قصّ اللصق عند **~٢٠٠٠ سطر**. وهذا يعني أمراً مهماً:

**ملف `1-schema.sql` (٣٠٥٤ سطراً) انقصّ أيضاً — وأنت حسبته نجح.**

قياس فعلي على ما يبقى لو قُصّ عند ٢٠٠٠:

| العنصر | الكامل | ما يبقى بعد القصّ | المفقود |
|---|---|---|---|
| جداول | ١٩ | **١١** | ❌ ٨ جداول |
| دوال | ٦٨ | **٣٠** | ❌ ٣٨ دالة |
| مشغّلات | ١٨ | **٩** | ❌ ٩ مشغّلات |
| مهام مجدولة | ٥ | **١** | ❌ ٤ مهام |
| منح صلاحيات | ٤٢ | **٢٧** | ❌ ١٥ منحة |

**«طلع صح» في المحرّر معناها أن ما وصل هو صحيح نحوياً — لا أن الملف كله وصل.**
لهذا نحتاج مقياساً، لا نظرة على كلمة Success.

### ولماذا لا يظهر خطأ؟

لأن اللصق يقصّ عند حدّ **سطر**، والسطر ٢٠٠٠ صادف أنه نهاية جملة كاملة.
فحُفظ الباقي كملف ناقص لكن **صالح نحوياً**. لو قُصّ داخل `$$` لظهر خطأ واضح —
وهذا كان سيكون أسهل. النقص الصامت هو الخطر.

## ✅ الحلّ: الأجزاء (كلها أقل من ٧٠٠ سطر)

`docs/sql-parts/schema/` — ٥ ملفات، أطولها **٦٨٨ سطراً**. لا يقصّها المحرّر أبداً.
والملفات مولّدة من `docs/schema.sql` **الكامل**، لا من نسخة مقصوصة.

## الخطوات بالترتيب

### ⓪ الإضافات (قبل أي SQL)

`Supabase → Database → Extensions` — فعّل:

- ✅ `pgcrypto`
- ✅ `pg_cron`

بدونهما: التشفير معطّل، والإفراج التلقائي عن الحجوزات لا يعمل، والنسخ المجدول لا يعمل.

### ① السكيما — ٥ لصقات

| # | الملف | الأسطر |
|---|---|---|
| ١ | `schema/schema-part-01.sql` | ٦٧٤ |
| ٢ | `schema/schema-part-02.sql` | ٦٦٠ |
| ٣ | `schema/schema-part-03.sql` | ٦٨٤ |
| ٤ | `schema/schema-part-04.sql` | ٦٨٨ |
| ٥ | `schema/schema-part-05.sql` | ٤٨٠ |

**بعد كل جزء:** `New query` جديد. لا تكتب فوق السابق.
**بعد الجزء الخامس:** شغّل `مقياس-الجاهزية.sql` — يجب أن يعطي 🟢.

> ⏱ الجزء الخامس فيه `select brc.archive_finished_cards();` — قد ينتهي بمهلة.
> المهلة هنا **ليست فشلاً**: الأجزاء قبله نجحت. راجع المقياس لتتأكد.

### ② البيانات — بالترتيب الرقمي

```
node tools/split-sql.mjs 2-data.sql --out docs\sql-parts\data
```

ثم الصق `2-data-part-01.sql` … بالترتيب. العدد بحسب حجمك (٤٤٠ بطاقة = ٨ أجزاء).

> ⚠️ الجزء الأول فيه `TRUNCATE`. على مشروع **جديد** لا خطر. على قاعدة فيها
> بيانات تريدها — **توقّف**.

### ③ تحقّق

شغّل `تحقق-النسخة.sql`:

- **① الأعداد** — قارنها بسطر «الأعداد» أعلى `2-data-part-01.sql`. يجب التطابق.
- **② سلامة الروابط** — كل الأرقام صفر.
- **③ الوظائف** — يعطي اسماً وهاتفاً مقنّعين، لا خطأ.

### ④ الإعدادات اليدوية (لا يمكن أن تكون في SQL)

| ما | أين | لماذا لا يُنقل |
|---|---|---|
| `app.brc_secret` | Database → Settings → Config | **سرّ** — لا يوضع في ملف يُنشر |
| `api URL` و`anon key` | `assets/js/supabase-config.js` | خاص بالمشروع |
| مخزن `job-images` | Storage → New bucket | ملفات، لا SQL |
| ربط حساب المدير | Authentication | كلمة المرور في `auth`، لا في `brc` |

بعد ضبط `app.brc_secret`: `select pg_reload_conf();`

### ⑤ الحسابات

حسابات الموظفين تُنقل في `brc.staff` (البيانات). لكن **كلمات المرور** في
`auth.users` — لا تُصدَّر عمداً (تصديرها خطر أمني). لكل موظف:

1. `Authentication → Users → Add user` بنفس البريد
2. `select brc.link_staff_by_email();` أو ربط `auth_id` يدوياً

## معايير «النسخة ناجحة» — لا تعتمد على الشعور

| # | المعيار | كيف تتحقق |
|---|---|---|
| ١ | 🟢 في مقياس الجاهزية | `مقياس-الجاهزية.sql` |
| ٢ | الأعداد مطابقة | `تحقق-النسخة.sql` ① |
| ٣ | صفر مخالفات | `تحقق-النسخة.sql` ② |
| ٤ | الدوال تعمل | `تحقق-النسخة.sql` ③ |
| ٥ | ٤ مهام مجدولة | `select * from cron.job;` |
| ٦ | بطاقة حقيقية تُفتح | امسح باركود بطاقة تجريبية من الموقع |
| ٧ | التقديم يعمل | قدّم ببطاقة اختبار ← تحقق من الفرصتين |

**لو نجحت ١–٥ فقط:** البيانات سليمة لكن الموقع لم يُختبر بعد.
**لو نجحت ٧:** النسخة تعمل فعلاً.

## أخطاء ستواجهها — ومعانيها الحقيقية

| الخطأ | المعنى | الحل |
|---|---|---|
| `relation "brc.X" does not exist` | جزئك لم يصل كاملاً أو تخطيت جزءاً | راجع المقياس — أكمل الناقص |
| `undefined_table cron.job` | `pg_cron` غير مفعّلة | Extensions → فعّلها → أعد الجزء ١ |
| `canceling statement … timeout` | الجزء بطيء على القاعدة | شغّله وحده، أو ارفع المهلة |
| `duplicate key` | لصقت البيانات مرتين | ابدأ من `2-data-part-01.sql` (يفرّغ) |
| `current transaction is aborted` | معاملة معلّقة | `rollback;` ثم أعد الجزء |
| `permission denied for schema brc` | لصقت كدور غير `postgres` | SQL Editor يعمل بـ`postgres` — تأكد |
