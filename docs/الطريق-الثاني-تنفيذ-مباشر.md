# الطريق الثاني — استرجاع بلا لصق ولا تقسيم

**لماذا هذا الملف؟** لأن لصق ثلاثين جزءاً في محرّر SQL عملٌ مكرّر ومعرّض للخطأ.
المحرّر يقصّ عند ~٢٠٠٠ سطر ويرفع «Success» — أخطر كذبة في يوم استرجاع.
هذا الطريق ينقل الملف كاملاً بأمر واحد.

---

## ما تحتاجه — مرة واحدة فقط

| العنصر | من أين |
|---|---|
| **Node.js 18+** | <https://nodejs.org> — الإصدار LTS |
| **ملف النسخة** `hrc-backup-….hrcbak` | من زر التنزيل في لوحة الإدارة |
| **كلمة مرور النسخة** | التي كتبتها أنت. لا تُحفظ في أي مكان |
| **رابط قاعدة المشروع الجديد** | Supabase → Project Settings → Database → **Connection string → URI** |

> ⚠️ في Supabase صار «Direct connection» يحتاج IPv6 أحياناً.
> الأسهل: استخدم **Session pooler** من نفس الصفحة، هو نفس الرابط ويقبل IPv4.

## الخطوات

### ١) ثبّت المكتبة (مرة واحدة)
```bash
cd "مسار-المشروع"
npm install pg
```

### ٢) انسخ الهيكل على القاعدة الجديدة
من `restore.html` نزّل ملف الهيكل، أو استخدم `docs/schema.sql` مباشرة:

```bash
psql "الرابط-مع-كلمة-السر" -f docs/schema.sql
```

> إن لم يكن `psql` مثبتاً عندك: من Supabase → **SQL Editor**، الصق
> أجزاء الهيكل الخمسة (٣١٥٤ سطراً لا تدخل مرة واحدة). هذه الطريق فقط هي
> التي تحتاج اللصق — والبيانات لا تحتاجها أبداً.

### ٣) انقل البيانات بأمر واحد
```bash
node tools/restore-portable.mjs "C:\HRC-Backups\hrc-backup-2026-11-15-0900.hrcbak" --database "الرابط-مع-كلمة-السر"
```

ستُطلب منك كلمة المرور **بلا صدى** (لا تظهر على الشاشة ولا تُسجَّل):

```
  الملف: ...\hrc-backup-2026-11-15-0900.hrcbak (1.9 MB)
  الصيغة: HRC-BACKUP/1 · AES-256-GCM · 310,000 دورة
  الأعداد: {"applicants":724,"attempts":1533,...}
  كلمة مرور النسخة: ████████

  متصل — تنفيذ السكربت…
  ✓ brc.applicants: 724 (المتوقع 724)
  ✓ brc.jobs: 22 (المتوقع 22)
  ✓ brc.job_attempts: 1533 (المتوقع 1533)
  ✓ brc.audit_log: 3775 (المتوقع 3775)
  ✓ اكتمل الاسترجاع وتحقّق — 8.3 ثانية
```

### ٤) تحقّق بنفسك
افتح المشروع، واقرأ الأعداد. **إن لم تطابق، الأمر يفشل بصوت عالٍ** —
لا يقول «اكتمل» وهو لم يكتمل.

---

## ماذا لو فشل؟

| الرسالة | المعنى | الحل |
|---|---|---|
| `كلمة المرور غير صحيحة` | الرمز خطأ **أو** الملف تغيّر | أعد التنزيل، وتأكد من طول الرمز المطبوع في الرسالة |
| `بصمة البيانات لا تطابق` | الملف عُدّل بعد إنشائه | استخدم نسخة أخرى من الـUSB |
| `relation "brc.xxx" does not exist` | الهيكل لم يُنفَّذ | كرّر الخطوة ٢ |
| `ECONNREFUSED` / `ENOTFOUND` | الرابط خطأ أو IPv6 | استخدم رابط **Session pooler** |
| `الاسترجاع لم يكتمل — N جدولاً` | التنفيذ بدأ وفشل في وسطه | اقرأ الجداول المذكورة، لا تعتمد على القاعدة |

---

## لماذا هذا آمن؟

- `BEGIN … COMMIT` + `session_replication_role = replica`: إما كل البيانات أو لا شيء.
- `TRUNCATE` في البداية: **لا تشغّله على قاعدة فيها بيانات حقيقية.**
- كلمة المرور لا تُطبع ولا تُسجَّل ولا تمرّ على سطر الأوامر (لا تظهر في `ps`).
- الملف لا يُعدَّل — يُقرأ فقط.

## الفرق عن الطريق الأول (اللصق)

| | لصق الأجزاء | هذا الطريق |
|---|---|---|
| عدد الخطوات | ٣٠+ لصقة | أمر واحد |
| خطر القصّ الصامت | **نعم** | لا (لا حدّ للحجم) |
| يحتاج إنترنت أثناء العمل | نعم | لا — يعمل ثم يرفع |
| يتحقق من الأعداد | يدوياً | **تلقائياً، ويفشل إن اختلفت** |
| يصلح لـ ٥٠٠٠ بطاقة | ٢٢ جزءاً | الأمر نفسه |
