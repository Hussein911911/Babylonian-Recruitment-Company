# الطريق الثاني — نسخ الموقع إلى مشروع جديد بأمان

**لمن هذا الملف؟** للمدير الذي يريد أن ينقل الموقع إلى مشروع Supabase جديد
(تجربة، أو بعد انقطاع الخدمة). مكتوب بلا مصطلحات.

---

## أولاً: اعرف ما ستنسخه قبل أن تنسخ

```bash
node tools/restore-plan.mjs hrc-backup-2026-11-16.hrcbak
```

هذه الأداة **لا تلمس قاعدة البيانات إطلاقاً**. تفكّ النسخة وتطبع:

```
          724  البطاقات
           22  الوظائف
        1,533  الفرص
        3,775  سجل التدقيق

  ✓  الوظائف والبطاقات والفرص
  ✗  صور الوظائف في Storage
        → تُرفع يدوياً — النسخة لا تحمل ملفات Storage
  ✗  كلمات مرور الحسابات
        → تُعاد من لوحة Supabase
```

**هذه أهم خطوة.** لأن أكثر ما يُفشل عملية نسخ هو مفاجأة لم تكن في الحساب:
الصور مفقودة، أو الموظفون لا يستطيعون الدخول.

---

## ثانياً: الخطوات الثماني

| # | الخطوة | ماذا يحدث |
|---|---|---|
| ١ | مشروع Supabase جديد فارغ | من لوحة Supabase |
| ٢ | نسخ الهيكل | `psql "الرابط" -f docs/schema.sql` |
| ٣ | **معاينة** | `--dry-run` — لا تلمس شيئاً |
| ٤ | **النقل** | الأمر الواحد — يمسح الهدف ثم ينقل |
| ٥ | ربط الموقع | `node tools/supabase-repoint.mjs <المعرف> <المفتاح>` |
| ٦ | رفع الصور | يدوياً في Storage |
| ٧ | كلمات مرور الموظفين | لوحة Supabase |
| ٨ | التحقّق من الأعداد | قارنها بالأرقام أعلاه |

---

## الحمايات الثلاث (لا يمكن تجاوزها)

### ١) المعاينة أولاً — `--dry-run`
```bash
node tools/restore-portable.mjs "النسخة.hrcbak" --database "الرابط" --dry-run
```
تطبع ما سيُنقل، وتتحقق أن الهيكل موجود، **وتمنع أي كتابة**. استخدمها دائماً.

### ٢) لا مسح بلا تأكيد
قبل التنفيذ، تقرأ الأداة القاعدة الهدف وتعرض:

```
  ⚠ القاعدة الهدف فيها بيانات! التنفيذ سيمسحها كلها:
       724  applicants
        22  jobs
     1,533  job_attempts

  ⚠ هذه ليست إضافة — بل استبدال كامل. ولا رجعة بعدها.

اكتب «أوافق على المسح» للمتابعة، أو Enter للإلغاء:
```

**«نعم» لا تكفي.** لا بدّ من كتابة العبارة كاملة. ولو ضغطت Enter،
تقول لك: «أُلغي — لم يُمسح شيء».

> للاستخدام الآلي (سكربت): `HRC_RESTORE_CONFIRM="أوافق على المسح"`
> ولا يُقبل غيرها.

### ٣) النقل مشفّر دائماً
لو كان الرابط بلا `sslmode`، تُضيفه الأداة تلقائياً وتُخبرك. أسماء وهواتف
٧٢٤ شخصاً لا تسير مكشوفة على الشبكة.

## ماذا لو فشل؟

| الرسالة | المعنى | الحل |
|---|---|---|
| `كلمة المرور غير صحيحة… (الطول N)` | الرمز خطأ أو الملف تغيّر | أعد التنزيل؛ الأرقام تكشف السبب |
| `القاعدة الهدف فيها بيانات` | حماية تعمل | تأكد أنك تشير إلى المشروع الصحيح |
| `الهيكل غير موجود` (في المعاينة) | لم تنفّذ الخطوة ٢ | `psql "الرابط" -f docs/schema.sql` |
| `ECONNREFUSED` / `ENOTFOUND` | الرابط خطأ أو IPv6 | استخدم **Session pooler** من Supabase |
| `الاسترجاع لم يكتمل — N جدولاً` | التنفيذ فشل في وسطه | لا تعتمد على القاعدة؛ اقرأ الأسماء |
| `تعذّر الاتصال… SSL` | الخادم لا يدعم TLS | لا تعطّله على Supabase — راجع الرابط |

---

## لماذا هذا آمن؟

- `BEGIN … COMMIT`: إما كل البيانات أو لا شيء.
- **لا يُكتب أي ملف SQL على القرص** — البيانات تُرسل من الذاكرة مباشرة.
  (طريق اللصق يُنزّل ملفاً فيه بيانات ٧٢٤ شخصاً بلا تشفير، ويبقى في التنزيلات.)
- كلمة المرور تُقرأ بلا صدى، ولا تُطبع، ولا تُسجَّل.
- بعد التنفيذ تُقرأ الأعداد من القاعدة وتُقارن بالنسخة — **لا «اكتمل» كاذبة**.
