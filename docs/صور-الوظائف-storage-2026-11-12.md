# نقل صور الوظائف إلى Storage

**التاريخ:** 2026-11-12 · **القرار:** «سويها أحسن» (بعد عرض المشكلة والأرقام)

---

## ١) لماذا

| القياس قبل | |
|---|---|
| قاعدة الشركة | ٥٦ م.ب |
| جدول التدقيق | ٢٤ م.ب (٤٣٪) |
| منه تعديلات الوظائف | **٢٠ م.ب (٣٦٪)** |
| سبب الحجم | ٣٨ تعديلاً يحمل صورة base64 مكرّرة |
| صورة واحدة | ٥٤٢ ك.ب تكرّرت ٣٨ مرة |

كل تعديل على وظيفة ينسخ صفّها كاملاً — **والصورة جزء منه** — إلى `audit_log.diff`.
٤ من ٢١ وظيفة كانت تحمل صورتها `data:image/jpeg;base64,…` داخل `image_url`.

---

## ٢) ما نُفِّذ

### أ) الخزنة

```sql
bucket: job-images · public: true · limit: 2MB · mime: jpeg/png/webp
```

### ب) سياسات RLS — أربع

| السياسة | العملية | الطبقة |
|---|---|---|
| `job_images_public_read` | SELECT | `anon` + `authenticated` — الصور تظهر للزوار |
| `job_images_staff_write` | INSERT | `brc.is_staff()` — الموظف والمدير |
| `job_images_staff_update` | UPDATE | `brc.is_staff()` |
| `job_images_admin_delete` | DELETE | `brc.is_admin()` |

### ج) النقل — بشرطين قبل أي استبدال

1. **بصمة الصورة**: `FFD8FF` لـJPEG · `89504E47…` لـPNG · `RIFF…WEBP` · `GIF`
2. **كتابة الصف**: `exists (select 1 from storage.objects …)`

لو فشل أي شرط، يبقى `data:` كما هو. **لا صورة تُفقد.**

### د) الواجهة

`Store.uploadJobImage()` ترفع الصورة عند الحفظ بدل تضمينها base64.
**الرجوع الآمن:** أي فشل → تُرجع base64. مُثبت بقطع الشبكة.

---

## ٣) النتيجة

| | قبل | بعد |
|---|---|---|
| `image_url` في الصف | ٥٤٢ ك.ب | **٩٤ بايت** |
| حجم قاعدة البيانات | ٥٦ م.ب | **٣٥ م.ب** |
| صور في Storage | — | ٤ (٦٦٦ ك.ب) |
| صور base64 في `jobs` | ٤ | **٠** |

---

## ٤) الإثبات

```
✔ المعاينة الجافة (dry_run)   → 4 صور، 0 أخطاء، بصمات صحيحة
✔ نسخة رجوع محفوظة            → brc.jobs_image_url_rollback_20261112 (888KB)
✔ التنفيذ                     → ok:true · moved:4 · failed:0
✔ التحقق في القاعدة           → still_embed:false لكل الأربع
✔ القراءة بدور anon           → الأربع ظاهرة
✔ الكتابة بدور anon           → 42501 row-level security ✅ مرفوض
✔ تحميل الصورة في متصفح       → 32×32 (محاكاة استجابة Storage)
✔ نمط البطاقة --img           → يقبل الرابط
✔ الرجوع الآمن عند قطع الشبكة → base64، بلا انهيار
```

**لم أستطع التحقق من الرابط العام من الساندبوكس** — النطاق `supabase.co` محجوب
هنا. تحققت بدلاً من ذلك من: وجود الصف، وسياسة القراءة، واستجابة المتصفح
لمحاكاة الرابط. **التأكيد النهائي من جهازك.**

---

## ٥) الرجوع (إن لزم)

```sql
update brc.jobs j
   set image_url = r.image_url
  from brc.jobs_image_url_rollback_20261112 r
 where r.id = j.id;
```

ثم حذف الصور من `job-images` إن أردت. **سجلات التدقيق القديمة ما تزال كما هي** —
لم يُحذف منها شيء.

---

## ٦) ما لم يتغيّر

- **صور الوظائف الأربع نفسها** — نفس الملفات، نفس الجودة، نفس البكسل.
- **الشكل على الموقع** — يتغيّر مصدر الصورة فقط، لا العرض.
- **سجلات التدقيق** — ٣٤٨٢ سجلاً كما هي، بلا حذف.
- **الأداء** — المستخدم لا يشعر بفرق. الاستثناء الأول: الصور تُحمَّل من Storage
  وتُخزَّن مؤقتاً سنة (`cacheControl: 31536000`).
