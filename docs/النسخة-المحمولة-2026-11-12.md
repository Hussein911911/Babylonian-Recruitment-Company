# النسخة المحمولة — تنزيل للجهاز واسترجاع مستقل

**التاريخ:** 2026-11-12 · **الطلب:** «اريد نسخة تنزل للجهاز نختارلها مسار... نكدر نسترجعها مستقلة»

---

## ١) المشكلة في النظام الذي كان قائماً

النسخ الاحتياطية الموجودة (`brc.recovery_copies`) **لا تحمي من السيناريو الذي وُجدت لأجله**.

```sql
-- recovery_save (2026-09-15)
select secret into strict k from brc.recovery_control where singleton;
insert into brc.recovery_copies(..., ciphertext)
values (..., extensions.pgp_sym_encrypt(p::text, k, 'cipher-algo=aes256, ...'));
```

المفتاح `k` **مخزّن في نفس القاعدة**. لو ضاع المشروع أو انحذفت القاعدة:

> المفتاح يضيع ← كل النسخ تصير كتلة مشفّرة بلا مفتاح ← لا استرجاع.

هذا ليس ثغرة أمنية — التشفير سليم. لكنه خيار معماري يعني أن النسخة **لا تحمي
من فقدان المشروع**، وهو أسوأ سيناريو في قائمة السيناريوهات.

## ٢) ما أُضيف

### الطبقات الثلاث

| الطبقة | الملف | الدور |
|---|---|---|
| **القاعدة** | `supabase/migrations/20261112040000_portable_backup_export.sql` | `brc.recovery_export_full()` — تُرجع البيانات خاماً، للمدير فقط |
| **المتصفح** | `assets/js/portable-backup.js` | تشفير AES-256-GCM بمفتاح مُشتق من كلمة مرور المالك |
| **الاسترجاع** | `restore.html` + `assets/js/restore-page.js` | صفحة مستقلّة تفتح الملف بلا اتصال |
| **التطبيق** | `tools/restore-portable.mjs` | ملف → SQL جاهز لـ PostgreSQL |

**النقطة الجوهرية:** المفتاح **لا يمرّ بالقاعدة إطلاقاً**. يُشتق داخل المتصفح من
كلمة مرور يكتبها المالك، ويبقى `non-extractable` في Web Crypto. لذلك الملف
قابل للفتح حتى لو لم تعد القاعدة موجودة.

## ٣) التشفير

| الخاصية | القيمة |
|---|---|
| الخوارزمية | AES-256-GCM (مصادقة مدمجة) |
| اشتقاق المفتاح | PBKDF2-SHA256 · ٣١٠٬٠٠٠ دورة (توصية OWASP 2023) |
| الملح | ١٦ بايت عشوائي لكل ملف |
| المتجه | ١٢ بايت عشوائي لكل ملف |
| المفتاح | `non-extractable` — لا يمكن تصديره من المتصفح |
| السلامة | SHA-256 للحمولة قبل التشفير، يُقارن بعد الفك |

**رفض التعديل:** GCM يرفض أي بايت معدَّل. أُضيفت بصمة SHA-256 مستقلة كطبقة
ثانية، ورُفض في الفحص أيضاً تغيير `checksum` أو `iterations`.

**لا نفرّق** بين «كلمة مرور خاطئة» و«ملف معدَّل» في الرسالة: التفريق يمنح
المهاجم إشارة مجانية.

### ما لا يُصدَّر

| الحقل | السبب |
|---|---|
| `staff.auth_id` | يربط بـ `auth.users` — خارج نطاق الاسترجاع |
| كلمات المرور | ليست في `brc.staff` أصلاً (Supabase Auth يخزّنها في `auth`) |
| `recovery_control.secret` | مفتاح التشفير القديم — لا لزوم له في نسخة محمولة |
| `auth.sessions` / `auth.refresh_tokens` | جلسات — لا معنى لها بعد الكارثة |

## ٤) الاستخدام

### أ) التنزيل (المدير فقط)

لوحة الموظفين ← الإعدادات ← **النسخ الاحتياطي والاسترجاع** ←
«🌐 **تنزيل نسخة إلى الجهاز**»

1. تُكتب كلمة مرور (١٠ محارف على الأقل) وتأكيدها.
2. يُقرأ عدد البطاقات وسجل التدقيق من القاعدة.
3. المتصفح يفتح نافذة **«حفظ باسم»** — تختار المسار بنفسك.
4. ينزل ملف `hrc-backup-YYYY-MM-DD-HHmm.hrcbak`.

> ⚠️ **احفظ كلمة المرور.** لا تُخزَّن في أي مكان. لا يمكن استعادتها.

### ب) الاسترجاع المستقل

**بلا إنترنت وبلا حساب وبلا قاعدة:**

1. افتح `/restore` (أو `restore.html` من الجهاز مباشرة).
2. اسحب ملف `.hrcbak` أو اختره.
3. تُعرض البيانات الوصفية (التاريخ، الحجم، الأعداد) بلا كلمة مرور.
4. أدخل كلمة المرور ← تُفكّ وتُتحقَّق البصمة.
5. نزّل **JSON مفتوح** أو **CSV للبطاقات**.

**الاسترجاع الفعلي إلى قاعدة:**

```bash
# يولّد SQL
node tools/restore-portable.mjs نسخة.hrcbak

# أو ينفّذ مباشرة على قاعدة جديدة
node tools/restore-portable.mjs نسخة.hrcbak --database "postgresql://..."
```

كلمة المرور تُقرأ من الطرفية **بلا صدى**، أو من `HRC_BACKUP_PASSWORD`.
لا تُمرَّر على سطر الأوامر (كانت ستظهر في `ps`).

## ٥) الحمايات المضافة

| # | الحماية | الإثبات |
|---|---|---|
| ١ | `is_admin()` في الدالة | موظف نُفِّذ عليه → `P0001: صلاحية المدير العام فقط` |
| ٢ | `revoke` عن `anon` و`public` | `has_function_privilege('anon',...)` = false |
| ٣ | حارس `Store.recoveryExportFull` | `!isAdmin()` → رفض قبل أي طلب |
| ٤ | حارس `portableDownload` | رسالة «صلاحية المدير فقط» |
| ٥ | `search_path` مثبّت | نفس نمط الـ٤٣ دالة الأخرى |
| ٦ | تدقيق كل تصدير | سطر في `audit_log`: «تصدير نسخة كاملة للجهاز» |
| ٧ | لا شبكة في صفحة الاسترجاع | صفر طلبات خارجية (٩ فحوص متصفح) |

**ملاحظة على `is_admin()`:** معرّفة `SECURITY DEFINER` وتقرأ من `brc.staff`،
فالتلاعب بحقل `role` في الـJWT لا ينفع — `auth.uid()` فقط هو ما يُقرأ.

## ٨) ما لم يُنفَّذ (يحتاج موافقة منفصلة)

**الكتابة المباشرة من صفحة الاسترجاع إلى قاعدة جديدة.**

الصفحة الحالية **تستخرج** البيانات وتتحقق منها. إعادة الإدخال تتم بـ
`tools/restore-portable.mjs`. جعل الصفحة تكتب بنفسها يحتاج شهادة اتصال
بقاعدة فارغة تُدخل في المتصفح — قرار أمني منفصل. لم أنفّذه.
