## 4) ما ينقص — مرتّباً بالأولوية

### 🔴 أولاً: أعِد النشر (بعد دمج هذا الفرع)

بمجرد دمج هذا الإصلاح في `main` سيبني Cloudflare بنجاح وينشر تلقائياً — لأن
الربط قائم أصلاً. **لا تحتاج مفاتيح API ولا ملف workflow ولا `dist/` يدوياً.**

> ⚠️ `docs/deploy-cloudflare.md` يوصي بإضافة `CLOUDFLARE_API_TOKEN` وملف workflow.
> **لا تفعل ذلك.** المشروع مربوط بـ Git فعلاً، وإضافة الملف تعني نشرين لنفس
> الموقع. الوثيقة مبنية على تشخيص خاطئ ويجب تصحيحها.

**تحقّق من إعدادات البناء في لوحة Cloudflare** (Settings → Builds & deployments):
الأسلم **Build command فارغ** و **Output = `.`** لأن الملفات المبنية مُودعة في
Git أصلاً. وإن كان هناك أمر بناء فليكن:
`npm ci && npm run build && npm run build:light && npm run dist` مع Output = `dist`.

### 🔴 ثانياً: الموقع يعرض وظائف وهمية للزائر

سكيما `brc` غير مقروءة من الخارج. الإصلاح في لوحة Supabase:

1. **Project Settings → API → Exposed schemas** → أضف `brc` → Save.
2. إن لم يكن المخطط مطبَّقاً: الصق `docs/schema.sql` في **SQL Editor** → Run.
3. أعد فحص `/supabase-check.html` حتى تظهر «جاهز للتسليم ✓».
4. أدخِل وظائف الشركة الحقيقية — وإلا بقي الزائر يرى بيانات `config.js` التجريبية.
