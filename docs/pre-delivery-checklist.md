# ✅ قائمة ما قبل التسليم للزبون

> هذه القائمة هي آخر ما يُنفَّذ قبل تسليم المنصة. لا تُسلِّم قبل أن تُصفَّر كلها.
> البند الأول **إلزامي**: هو الفرق بين نسخة مطوّر ونسخة عميل.

---

## 1) ✅ حذف كلمات المرور من الكود (الأهم) — منجز

**تم:** `assets/js/config.js` يحمل `users: []` (لا حسابات في الكود إطلاقاً)، و
`assets/js/supabase-config.js` يحمل `enforceAuth: true`. من يفتح «عرض المصدر»
لا يجد أي كلمة مرور، والدخول المحلي مرفوض في طبقة البيانات نفسها.

ما نُفِّذ (للسجل):
- حُذفت مصفوفة `users` من `assets/js/config.js` (`users: []`).
- ضُبط `enforceAuth: true` في `assets/js/supabase-config.js`.
- أُعيد البناء: `npm run build && npm run build:light`.

**التحقق الدائم:** افتح اللوحة وحاول الدخول بـ `admin / admin123` → يجب أن يُرفض.
وافتح اللوحة بحسابك الرسمي (Supabase Auth) → يجب أن يعمل.
(اختبار `tests/dashboard-cloud.mjs` يثبت هذا السلوك آلياً — الباب مغلق ولا يُفتح
لأجل الاختبارات: السيناريوهات الانتقالية تُحاكى بfixtures داخل بيئة الاختبار وحدها.)

> ⚠️ الترتيب مهم: **أنشئ الحسابات أولاً** ثم احذف كلمات المرور. لو عكست الترتيب
> لن يستطيع أحد الدخول حتى تُنشئ الحسابات.

---

## 2) فحص الجاهزية — الجواب القاطع

افتح `/supabase-check.html` ونفّذ **فحص حساب الموظف**.
يجب أن ترى: **«جاهز للتسليم ✓»**

الفحص يُنشئ وظيفة اختبارية (`BRC-TEST-…`) ثم يحذفها فوراً، ويتحقق من:
الدخول · سطر `brc.staff` · قراءة الإعدادات والوظائف والتدقيق · **إدراج فعلي · حذف فعلي**.

---

## 3) المخطط والصلاحيات في المشروع

- [ ] `docs/schema.sql` مطبَّق في `SQL Editor` (أو ملف الهجرة في `supabase/migrations/`).
- [ ] سكيما `brc` مضافة في `Project Settings → API → Exposed schemas`.
- [ ] `app.brc_secret` مضبوط (للبصمة في الكيو آر كود).
- [ ] `pg_cron` و`pgcrypto` مفعّلان.
- [ ] الحماية `RLS` فعّالة على الجداول الستة (فحص `supabase-check.html` يتحقق منها).

---

## 4) الترتيب والتحديث اللحظي

- [ ] اسمح للمشروع بالنشر على نطاق الزبون في `Realtime` (الجداول الأربعة: `jobs` · `job_attempts` · `audit_log` · …).
- [ ] **النشر على Cloudflare Pages وحده**: المشروع مربوط بالمستودع، Production branch = `main`،
      Build command فارغ، Output = `.`، ومعاينات الفروع مفعّلة (انظر `docs/deploy-cloudflare.md`).
- [ ] **إلغاء Render**: حُذفت الخدمة من لوحة Render وصار رابط `onrender.com` متوقفاً (404)،
      وأُزيل من كل مكان يُشارَك مع الناس.
- [ ] تحقّق أن الزائر لا يرى أي واجهة تقديم استمارة أو تحقق: الصفحة الرئيسية + `/verify`
      (يجب أن تعرض بوابة «خاص بموظفي الشركة والإدارة») + الملف المستقل.

---

## 5) الإعدادات النهائية في المشروع

- [ ] `enforceAuth: true` (انظر البند 1).
- [ ] كلمة مرور قوية لحساب المدير، ولا مشاركة لحسابات الموظفين.
- [ ] تأكيد أن `assets/js/supabase-config.js` فيه **المفتاح العام فقط**
      (لا `service_role` ولا كلمة مرور قاعدة بيانات ولا `app.brc_secret`).

---

## 6) اختبارات نهائية (أمر واحد)

```bash
npm run test:all
```

يجب أن تنتهي كل الاختبارات بنجاح. ثم:

```bash
node tools/loadtest.mjs --users=100 --secs=8
```

لمشاهدة وزن كل صفحة وزمن الاستجابة.

---

## 7) ملاحظات يُفضَّل إبلاغ الزبون بها

- **النسخ الاحتياطي:** نسخ Supabase التلقائي (PITR/يومي) حسب الخطة. الاستيراد
  والتصدير اليدوي متاحان من داخل المنظومة للطباعة والأرشفة.
- **الطباعة:** استمارة A4 وكيو آر كود تحقق يعملان بلا إنترنت في
  `brc-standalone.html` (ملف واحد يُشارك بالواتساب).
- **الأمان:** كل عملية مُسجَّلة في سجل التدقيق (مستخدم · وقت · IP · التفاصيل).
