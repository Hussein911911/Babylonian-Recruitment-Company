## ٢. النسخة على USB — الطريقة السهلة

**ما تحتاجه:** متصفح Chrome أو Edge · فلاش USB · كلمة مرور تختارها.

### الخطوات

| # | الخطوة |
|---|---|
| ١ | وصّل الفلاش USB |
| ٢ | لوحة المدير ← **«النسخ الاحتياطي والاسترجاع»** |
| ٣ | قسم **«نسخة محمولة تنزل على جهازك»** ← اضغط **«تنزيل نسخة إلى الجهاز»** |
| ٤ | اكتب كلمة مرور طويلة (١٠ محارف فأكثر) — **مرتين** |
| ٥ | في الأعلى: **«مجلد الحفظ»** ← اضغط **«تغيير…»** واختر مجلد `HRC-Backups` على الفلاش |
| ٦ | اضغط **تنزيل** |

**ما يحدث:** تُفتح نافذة اختيار مجلد ← تختار ← الملف يُكتب **هناك مباشرة**، لا في التنزيلات.

### بعد أول مرة

صندوق **«مجلد الحفظ»** يعرض اسم المجلد دائماً مع شارة:

```
مجلد الحفظ                        [ تغيير… ]
HRC-Backups  [ جاهز ]      ← تُحفظ بضغطة واحدة
```

أو:

```
HRC-Backups  [ يطلب تأكيداً ]   ← يظهر شريط «السماح» قبل الحفظ
```

**اسم المجلد لا يختفي.** و«تغيير…» يفتح الاختيار من جديد ويحدّث الاسم فوراً.

### ⚠️ حدود هذه الطريقة — بصراحة

| الحدّ | التفصيل |
|---|---|
| **يدوية** | لا تعمل وحدها. تكرّرها أنت. |
| **لا يعرض المسار الكامل** | Chrome يُظهر **اسم المجلد** فقط (`HRC-Backups`)، لا `D:\HRC-Backups`. لو كشف المسارات لأمكن لأي موقع رسم خريطة جهازك. |
| **قد يطلب تأكيداً** | بعد إغلاق المتصفح قد يظهر شريط «السماح». لا توجد واجهة برمجية تلغي هذا. |
| **كلمة المرور لا تُستعاد** | ضاعت = الملف لا يُفتح. اكتبها في مكان آمن. |

### تحقّق بنفسك

بعد الرسالة «كُتبت النسخة على الـUSB … تحقّقت من الملف بعد الكتابة»:

```
This PC ← الفلاش ← HRC-Backups
```

لازم تجد ملفاً باسم `hrc-backup-YYYY-MM-DD-HHMM.hrcbak`، حجمه **١٠٠–٣٠٠ كيلوبايت**.

> الكود يقرأ الملف من الفلاش **مرة ثانية** ويقارن بصمته SHA-256. لكن **افتح الفلاش بعينك أول مرة** — الثقة العمياء ليست تحقّقاً.

## ٣. النسخ التلقائي داخل الموقع

**جاهزة الآن — لا شيء تثبّته.**

- القاعدة تحفظ **آخر ٣ نسخ** تلقائياً، والأقدم يُحذف.
- الجدولة: **الجمعة ٢٣:٠٠** بتوقيت بغداد.
- تعمل حتى لو كانت اللوحة مغلقة.

### تغيير الجدولة

لوحة المدير ← «النسخ الاحتياطي والاسترجاع» ← **«جدولة النسخ التلقائي»**:

```
○ كل عدد ساعات    ← ١، ٢، ٣، ٤، ٦، ٨، ١٢، ٢٤
○ كل يوم          ← ساعة محدّدة
○ كل عدد أيام     ← ١ إلى ٩٠
○ أيام محدّدة     ← نوّر الأيام
```

ثم **«حفظ الجدولة»**.

> **نصيحة:** الأسبوعي يفقد حتى ٧ أيام عند الاسترجاع. اليومي يفقد ٢٤ ساعة.
> النسخة ≈ ١١٥ كيلوبايت — فالتخزين ليس عائقاً.

### الاسترجاع من النسخ التلقائية

لوحة المدير ← «النسخ المحفوظة» ← اختر نسخة ← **«استرجاع»**
← راجع المعاينة ← اكتب كلمة **«استرجاع»** ← تأكيد.

> يلزم تسجيل دخول جديد بعد الاسترجاع. تُحفظ نسخة أمان قبل العملية.

## ٤. كيف تستفيد من نسخة USB

### أ) فحص النسخة (بلا أي تغيير)

افتح **`restore.html`** ← اسحب الملف ← اكتب كلمة المرور ← **«فكّ التشفير»**.

سترى: عدد الوظائف · البطاقات · الفرص · سجل التدقيق، وجدولاً لكل واحد.

> يعمل بلا إنترنت. من الموقع يحتاج جلسة مدير؛ من جهازك (`file://`) يعمل دائماً.

### ب) الأزرار المتاحة بعد الفكّ

| الزر | ما يعطيك | متى تستخدمه |
|---|---|---|
| **تنزيل JSON** | كل البيانات ملفاً واحداً مفتوحاً | نسخ احتياطي إضافي، أو مراجعة |
| **تنزيل البطاقات CSV** | البطاقات في Excel | بحث ومراجعة |
| **تنزيل كل الجداول CSV** | ملف لكل جدول | تحليل في Excel |
| **تنزيل 1-schema.sql** | بنية القاعدة كاملة | **أول ملف** لقاعدة جديدة |
| **تنزيل 2-data.sql** | البيانات كـSQL | **ثاني ملف** لقاعدة جديدة |
| **إغلاق** | يمحو كل شيء من الذاكرة | بعد الانتهاء |

> ⚠️ **الترتيب إلزامي:** `1-schema.sql` أولاً، ثم `2-data.sql`. العكس يفشل.

## ٥. يوم الكارثة — ضاع مشروع Supabase

### جهّز قبل الكارثة

النسخة على الفلاش فيها **البيانات فقط**. أضف إليها الأداة والكود:

```
D:\HRC-Backups\
   ├── hrc-backup-2026-11-15-2145.hrcbak   ← نسختك
   ├── restore.html                         ← انسخه من المشروع
   └── assets\                              ← المجلد كاملاً
```

> الكود على GitHub محفوظ، لكن **لو ضاع الوصول** فلن تجد ما تنزّله.
> من GitHub: زر **Code** ← **Download ZIP**.

### الخطوات

| # | أين | ماذا |
|---|---|---|
| ١ | supabase.com | **New project** ← اسم + كلمة سر قوية + أقرب منطقة |
| ٢ | Supabase | **Database ← Extensions** ← فعّل **`pgcrypto`** و **`pg_cron`** |
| ٣ | من الفلاش | افتح `restore.html` ← اسحب النسخة ← كلمة المرور ← فكّ |
| ٤ | من الصفحة | **تنزيل 1-schema.sql** |
| ٥ | Supabase | **SQL Editor** ← الصق الملف ← **Run** ← انتظر «Success» |
| ۶ | من الصفحة | **تنزيل 2-data.sql** |
| ۷ | Supabase | **SQL Editor** ← الصق ← **Run** |
| ۸ | Supabase | **Settings ← API** ← انسخ `URL` و `anon key` |
| ۹ | المشروع | ضعهما في `assets/js/supabase-config.js` |
| ۱۰ | GitHub | ارفع الموقع |
| ۱۱ | Supabase | **Authentication ← Users ← Add user** ← بريدك |
| ۱۲ | SQL Editor | أنشئ صفّ المدير (الكود أدناه) |

```sql
insert into brc.staff (auth_id, username, full_name, role)
select id, 'admin', 'المدير', 'admin'
from auth.users where email = 'بريدك@مثال.com';
```

> ⚠️ **pgcrypto قبل أي SQL.** بدونه يتوقف الملف عند السطر الأول ولا يُنشأ جدول واحد.

### ما يُسترجع وما لا

| ✅ يُسترجع | ❌ لا يُسترجع |
|---|---|
| البطاقات · الوظائف · الفرص | كلمات المرور (تُنشأ من جديد) |
| سجل التدقيق الكامل | ملفات صور Storage (الروابط فقط) |
| الإعدادات · أرقام البطاقات المُصدرة | مفتاح المشروع `anon` (جديد) |

## ٦. جرّبها الآن — أهم خطوة

```
١. خذ نسخة على الفلاش
٢. انقر restore.html مرتين (من الفلاش — بلا إنترنت)
٣. اسحب النسخة ← اكتب كلمة المرور
٤. تأكد أنك ترى الأعداد: ٤٤٠ بطاقة · ٤٧ وظيفة
٥. اضغط «تنزيل 1-schema.sql» — نزّل الملف
٦. احذفه (كان تجربة)
```

**ثلاث دقائق.** ولماذا؟ لأن كلمة مرور منسيّة تُكتشف في **أسوأ وقت**.

> **نسخة لم تُجرَّب ليست نسخة.**

## ٧. راقب هذه كل شهر

1. لوحة المدير ← هل النسخ التلقائية تعمل؟
2. خذ نسخة USB جديدة
3. افتح `restore.html` وتأكد أن الملف يُفتح
4. **كل ٣ أشهر:** جرّب `1-schema.sql` على مشروع تجريبي

## ٨. ملاحظات USB — بصراحة

| | |
|---|---|
| **الحجم** | ٨ جيجا تكفي سنوات. النسخة ≈ ١١٥ كيلوبايت. |
| **النوع** | لا تشترِ الأرخص. SanDisk أو Samsung. |
| **العمر** | الفلاش الرخيص يفقد بياناته بصمت إذا بقي مفصولاً سنوات. |
| **نسختان** | فلاش ثانٍ في مكان آخر (البيت) أفضل من الأول المحسّن. |
| **مفصول وقت النسخ** | لا نسخة ذلك اليوم. النسخة الأصلية على القرص تبقى سليمة. |

## ٩. النسخ التلقائي على USB — غير مُفعّل

الطريقة في القسم ٢ **يدوية**. لجعلها تلقائية بالكامل يلزم:

- Node.js على الحاسبة
- أدوات PostgreSQL (`pg_dump`)
- مستخدم قاعدة **قراءة فقط** (غير موجود حالياً)
- التحقق من شهادة SSL تجربةً فعلية

**لم يُنفَّذ بعد.** إن أردته، فهو مشروع منفصل يحتاج وقتاً وتجربة.
