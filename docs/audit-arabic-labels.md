# «العملية» و«التفاصيل» بالعربية في سجل التدقيق

**التاريخ:** 2026-11-07 · **الطلب:** «شوف بالسجل عندك هاي كلمات انكليزيه اريد العمليه والتفاصيل بالعربي … بترتيب احتارفي» (لقطة شاشة من لوحة الموظفين على الجوال: `تعديل applicants` في «العملية» و`تغيير في applicants` في «التفاصيل»).

## من أين جاءت الكلمات الإنكليزية؟

مشغّل التدقيق في القاعدة `brc.trg_audit()` (`docs/schema.sql`) يكتب لكل صفّ يتغيّر:

```sql
case tg_op when 'INSERT' then 'إضافة' when 'UPDATE' then 'تعديل' else 'حذف' end || ' ' || tg_table_name,
...
'تغيير في ' || tg_table_name,
```

أي أن **`action` و`details` تُخزَّن مختلطة**: العربية + اسم الجدول الخام (`applicants` / `jobs` / `job_attempts`). الواجهة كانت تعرض `details` كما هو، وتُترجم `action` فقط إذا طابق القاموس **بالكامل** — فالجمل المختلطة كانت تمرّ كما هي. كذلك بعض سجلات المتجر المحلي تحمل تفاصيل `JSON.stringify` بمفاتيح إنكليزية (`{"name":…,"role":"admin","password":…}`، و`{"t":…,"g":…,"s":…}`).

## القرار المهني

**لا تعديل على القاعدة ولا على Supabase ولا هجرة (migration).** سجل التدقيق دليلٌ قانوني: تُترك قيمه الخام كما كُتبت، وتُعرَّب **طبقة العرض فقط** في الواجهة. هكذا تُصلَح كل الصفوف المخزَّنة سلفاً والجديدة معاً، بلا انتظار تشغيل SQL على الإنتاج، وبلا فقدان الدليل الأصلي.

## ما الذي تغيّر

| الملف | التغيير |
| --- | --- |
| `assets/js/dashboard.js` | قاموس `AUDIT_WORD` لأسماء الجداول/الحقول/الحالات، وقاموس `AUDIT_PHRASE` لجمل «تغيير في …» بصيغة عربية سليمة، وقاموس `AUDIT_FIELD` لمفاتيح JSON. دالة `auditText()` واحدة تُستبدل بها كل الكلمات اللاتينية المعروفة داخل الجمل المختلطة، وتُحوّل تفاصيل JSON إلى سطر مقروء («الاسم: أحمد · الرتبة: مدير عام · كلمة المرور: محجوب»). كلمات المرور/الأسرار تُحجب بكلمة عربية «محجوب» (لا نقاط تربك اتجاه النص). |
| `assets/js/dashboard.js` | `auditEntityLabel` / `auditActionLabel` / **`auditDetailsLabel`** الجديدة تُطبَّق على: جدول السجل، خيارات فلاتر «العملية/القسم»، ودائرة «آخر العمليات» في الصفحة الرئيسية. |
| `assets/js/dashboard.js` | **تصدير CSV** صار بالتسميات العربية أيضاً (القيم الخام تبقى في القاعدة). |
| `assets/js/store.js` | خطاف `setAuditDisplayLabels()` يُضاف إلى **نص البحث فقط**: البحث بـ«بطاقة» يجد سطراً خاماً فيه `applicants`، والبحث بالكلمة الخام يبقى عاملاً. لا يمسّ الفلاتر ولا التصدير ولا البيانات. |
| `sw.js` | `hrc-cache-v155` كي لا يعلق زائر على نسخة قديمة من `dashboard.js` / `store.js`. (رُفعت لاحقاً إلى `hrc-cache-v156` ثم `v157` مع استعادة تصميم وظائف البطاقة وإحكام بطاقة الفرص — انظر `docs/card-chances-redesign.md`). |
| صفحات مبنية | `index.html`، `verify.html`، `dashboard.html`، `404.html`، `hrc-standalone.html`، `hrc-light.html` أُعيد بناؤها. |

**ما بقي كما هو:** `docs/schema.sql` والمشغّل (القيم الخام)، بيانات Supabase والإنتاج، الفلاتر ومنطق الصلاحيات، أعمدة الجدول الستة، الأكواد المطبوعة (`HRC-1042` / `4SC` / عناوين الشبكة) لأنها معرّفات لا كلمات، واتجاه `dir="ltr"` لها.

أمثلة النتيجة:

| قبل | بعد |
| --- | --- |
| `تعديل applicants` | `تعديل بطاقة` |
| `تغيير في applicants` | `تعديل بيانات البطاقة` |
| `إضافة jobs` / `تغيير في jobs` | `إضافة وظيفة` / `تعديل بيانات الوظيفة` |
| `حذف job_attempts` | `حذف فرصة` |
| `{"name":"أحمد","role":"admin","password":"…"}` | `الاسم: أحمد · الرتبة: مدير عام · كلمة المرور: محجوب` |
| `{"t":"مهندس","g":"بابل","s":"available"}` | `العنوان: مهندس · المحافظة: بابل · الحالة: متاحة` |

## الفحوص

```bash
npm run build && npm run build:light
npm run test:audit-arabic           # 25 / 0  (جديد، jsdom على اللوحة الحقيقية)
npm run test:audit-arabic-browser   # 14 / 0  (جديد، Chromium 375px + 1440px)
npm run test:audit-search           # 24 / 0  (لا انحدار في البحث/التصدير/الصلاحيات)
```

- **`tests/audit-arabic-labels.mjs`**: يحقن صفوفاً تحاكي القاعدة والسجلات المحلية، ويتأكد من خلوّ «العملية» و«التفاصيل» من أي كلمة لاتينية، وصحة الجمل المعرّبة، وتعريب «القسم» والفلاتر و«آخر العمليات»، وعمل البحث بالعربية والخام، وتعريب التصدير، وحجب كلمة المرور، و**بقاء القيم الخام في المتجر بلا تعديل**، وصفر أخطاء JavaScript، وتضمين الملفات المبنية للمنطق.
- **`tests/audit-arabic-labels-browser.mjs`**: Chromium حقيقي بسجل معزول في `localStorage` (بلا اتصال بالإنتاج)، على 375px و1440px: صفر أخطاء، لا كلمات إنكليزية، لا تمرير أفقي للصفحة، الأكواد باقية، ولقطتا مراجعة في `tests/.tmp/audit-arabic-*.png`.
- بقية الحزم بعد التغيير: `npm test` 140/0 · `test:jobs-show-more` 45/45 · `test:header-nav` 29/0 · `test:header-nav-browser` 56/0 · `e2e` 103/0 · `test:apply` 117/0 · `brand` · `job-filters` · `audit-search` 24/0 · تسع حزم متصفح · `audit` 147/4/0 (مثل الأساس) · `schema` 302/6 (مثل الأساس) · `perf` 34/3 (مثل الأساس).

> لو أُريد يوماً أن تُكتب الصفوف **الجديدة** عربيةً في القاعدة نفسها، فذلك هجرة SQL منفصلة على `brc.trg_audit()` تُشغَّل في Supabase؛ لا حاجة إليها الآن لأن طبقة العرض تعرّب القديم والجديد معاً.
