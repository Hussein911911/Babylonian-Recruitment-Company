# التخزين المؤقت الذكي وإعادة التحقق الفوري (ISR)

> كيف تُخزَّن بيانات الوظائف، وكيف تُحدَّث فوراً عند أي تعديل من اللوحة — بلا إعادة بناء.

## المشكلة قبل

كل زائر يفتح الصفحة الرئيسية كان يُنزل بيانات الوظائف من قاعدة Supabase مباشرة.
مع كل تحميل للصفحة، وكل تنقّل، وكل زائر جديد: استعلام كامل على `public_jobs`
(وهو view فيه عدّ مترابط لكل صف). لا كاش مشترك بين الزوار إطلاقاً.

## الحل — ثلاث طبقات

```
زائر  ──►  [1] كاش CDN الحافة   ──►  [2] Supabase  ──►  [3] كاش المتصفح
             30 ثانية + SWR          public_jobs         5 دقائق (جلسة)
```

### [1] كاش حافة Cloudflare — `_headers`

```
/rest/v1/public_jobs*
  Cache-Control: public, s-maxage=30, stale-while-revalidate=300
```

- **`s-maxage=30`** → CDN يخدم النسخة المخزّنة ٣٠ ثانية لكل العالم. كل زائر داخل
  النافذة = **صفر استعلام** على القاعدة.
- **`stale-while-revalidate=300`** → بعد ٣٠ ثانية يُقدَّم القديم فوراً (سرعة)
  ويُحدَّث في الخلفية (حداثة). المستخدم لا ينتظر أبداً.
- النتيجة: من استعلام لكل زائر → **استعلام واحد كل ٣٠ ثانية** كحد أقصى.

### [2] إعادة التحقق الفوري — `functions/api/revalidate.js`

عند أي تعديل وظيفة، تُنادي اللوحة المسار فيُحذف الكاش **فوراً** بدل انتظار
٣٠ ثانية. هذا هو **On-Demand Revalidation** الحقيقي: تحديث عنصر واحد، لا
إعادة بناء للموقع.

```
POST /api/revalidate
x-hrc-timestamp: <ms>
x-hrc-signature: <HMAC-SHA256(secret, timestamp + "." + body)>
body: {"paths":["/rest/v1/public_jobs"],"reason":"job-create"}
```

**متى تُستدعى؟** تلقائياً من `assets/js/revalidate.js` مربوطاً في `store.js`:

| العملية | الوسم |
|---|---|
| إضافة وظيفة (`createJob`) | `job-create` |
| تغيير حالة وظيفة (`setJobStatus`) | `job-status` |
| حذف وظيفة (`deleteJob`) | `job-delete` |

إضافة بطاقة أو استمارة **لا** تُطلق إشعاراً — الكاش خاص بالوظائف فقط.

### [3] كاش المتصفح — `assets/js/cloud.js`

قائم من قبل: ذاكرة جلسة ٥ دقائق (`PUB_CACHE_TTL`) للعرض الفوري عند التنقّل
داخل التبويب، مع تحديث صامت في الخلفية.

## التفعيل على Cloudflare

### ١. اضبط السرّ

Cloudflare Dashboard → Pages → المشروع → **Settings → Environment variables**:

| الاسم | القيمة | إلزامي |
|---|---|---|
| `HRC_REVALIDATE_SECRET` | سلسلة عشوائية طويلة (٣٢ حرفاً+) | ✅ |
| `HRC_ALLOWED_ORIGIN` | `https://نطاقك` | اختياري |

> ⛔ **لا تكتب السرّ في أي ملف بالمستودع.** الدالة تقرأه من البيئة، والفحص
> `tests/revalidation.mjs` يفشل إذا وُجد سرّ مكتوب في الكود.

### ٢. اضبط سرّ التطوير محلياً (اختياري)

في وحدة تحكم المتصفح على `localhost`:

```js
window.HRC_CONFIG.revalidate.devSecret = 'نفس-السرّ';
```

بلا هذا يبقى الموقع يعمل، ويعتمد على كاش الحافة (تأخير ≤٣٠ ثانية).

### ٣. تحقق

```bash
node tests/revalidation.mjs        # ٤٩ فحصاً بلا شبكة
```

أو يدوياً على الخادم المحلي:

```bash
curl -X POST http://localhost:4173/api/revalidate \
  -H "x-hrc-timestamp: $(date +%s)000" \
  -H "x-hrc-signature: <التوقيع>"
```

## الأمان

| الخطر | الحماية |
|---|---|
| طلب عابر يحذف الكاش | توقيع HMAC-SHA256 على (طابع + جسم) — بلا السرّ لا توقيع |
| إعادة تشغيل طلب مسروق | نافذة **٥ دقائق** فقط؛ الأقدم يُرفض |
| تخمين السرّ | مقارنة بزمن ثابت (`safeEqual`) لا تكشف عدد الأحرف المطابقة |
| حذف كاش صفحات أخرى | **قائمة بيضاء** — `/rest/v1/public_jobs` فقط |
| سرّ مسرّب في الكود | يُقرأ من `env` فقط؛ فحص آلي يمنع كتابته |
| نسيان ضبط السرّ | المسار يرد **503** ولا يعمل مفتوحاً |

**الفشل آمن:** لو تعذّر الاتصال بالمسار، لا تتعطل الواجهة — الكاش يسقط وحده
بعد ٣٠ ثانية. لا رسالة خطأ للزائر، ولا انهيار.

## ما لم يُفعل — ولماذا

**لم نُنشئ صفحات HTML مبنية مسبقاً (SSG).** المتطلبات ذكرت ISR ضمن Next.js
عادةً، لكن المشروع **موقع ساكن على Cloudflare Pages بلا خادم Node**. البديل
المكافئ والمطابق للغرض:

| ما طُلب | ما نُفّذ | لماذا |
|---|---|---|
| كاش بيانات مع revalidate | `_headers` + s-maxage + SWR | نفس النتيجة: صفر استعلام لكل زائر |
| On-Demand Revalidation API | `functions/api/revalidate.js` | Pages Function = المسار الوحيد المتاح |
| تحديث العنصر المعدّل فقط | قائمة مسارات محدّدة | لا إعادة بناء كاملة |

`tools/serve.mjs` يحاكي نفس المسار محلياً عبر `tools/revalidate-core.mjs`
المشترك، فلا فرق سلوكياً بين المعاينة والإنتاج.

## الملفات

| ملف | دوره |
|---|---|
| `_headers` | كاش الحافة + رؤوس المسار |
| `functions/api/revalidate.js` | Pages Function (إنتاج) |
| `tools/revalidate-core.mjs` | النواة المشتركة (توقيع/تحقق) |
| `assets/js/revalidate.js` | عميل اللوحة (إرسال + خنق) |
| `assets/js/store.js` | ٣ نقاط تعديل → إشعار |
| `tools/serve.mjs` | محاكاة محلية للمسار |
| `tests/revalidation.mjs` | ٤٩ فحصاً |
