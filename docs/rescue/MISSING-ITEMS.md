## ❌ ٣. الملف الكامل للبيانات (`auth.users`) — لم يُصدَّر

**الحالة:** موصل Supabase يقصّ أي نتيجة أكبر من ~٥٠ ك.ب. جدول `audit_log` وحده
٢٣ م.ب. **محاولة تصديره عبر الموصل ستنتج ملفاً مقطوعاً يدّعي السلامة** — وهذا أسوأ
من عدم التصدير.

**الأثر:** كلمات مرور الموظفين الثلاثة **لن تُنقل** ما لم يُصدَّر `auth.users`.

**الطريقة المدعومة (من جهازك، لا تمرّر كلمة المرور في المحادثة):**

```bash
# ١) من لوحة Supabase: Project Settings → Database → Connection string → URI
#    ضع كلمة المرور في متغير بيئة محلي، لا في الأمر نفسه
export DATABASE_URL='postgresql://postgres:...@db.vqsvztudvfukyuerzcgx.supabase.co:5432/postgres'

# ٢) صدّر (pg_dump مرافق لـ PostgreSQL 17)
pg_dump "$DATABASE_URL" --schema=brc --schema=auth --no-owner --no-privileges \
  --encoding=UTF8 -f HRC-FULL-2026-11-18.sql
```

> ⚠️ `--schema=auth` هو ما يحمل كلمات المرور المشفّرة. بلا هذا العلم، الحسابات تُفقد.
> الهاشات bcrypt — **قابلة للنقل كما هي** عبر استيراد نفس الجدول في المشروع الجديد.
