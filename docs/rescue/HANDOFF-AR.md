## الأخطاء الثلاثة التي ستقع فيها إن لم تقرأ

### ❌ ١. ستظن أن SQL فيه كل شيء

`docs/schema.sql` يحمل **الهيكل فقط**: جداول، دوال، فهارس، سياسات، مشغّلات.
**لا يحمل:**

- صفوف البيانات (٧٢٥ عميلاً، ١٥٣٥ محاولة…)
- **٤ مهام pg_cron** ← القاعدة تعمل بلا أتمتة بصمت
- **صور التخزين** ← وظائف بصور مكسورة
- **`auth.users`** ← لا يستطيع أحد تسجيل الدخول
- السكيما المعلنة `brc` ← موقع يفتح فارغاً

كل هذه في `config/` أو في `MISSING-ITEMS.md`.

### ❌ ٢. ستحاول تصدير البيانات عبر موصل Supabase

**لا تفعل.** الموصل يقصّ أي نتيجة أكبر من ~٥٠ ك.ب، و`audit_log` وحده ٢٣ م.ب.
محاولة التصدير تنتج ملفاً مقطوعاً يبدو سليماً — كارثة مؤجلة.

الطريقة الصحيحة: `pg_dump` مع `--schema=auth` (انظر `MISSING-ITEMS.md` §٣).

### ❌ ٣. ستعدّل مكاناً واحداً لمعرّف المشروع

المعرّف مكتوب في **٥ أماكن**:

1. `assets/js/supabase-config.js` (الرابط والمفتاح)
2. `_headers` (CSP: `connect-src` و`img-src`)
3. `sw.js` (أصل الصور)
4. `<link rel="preconnect">` في ٧ صفحات
5. (إن أضفت) `functions/api/revalidate.js`

تعديل الأول وحده = موقع يفتح ولا يتصل. **استخدم:**

```bash
node tools/supabase-repoint.mjs <ref> <key>
```

الأداة تعدّل الخمسة وتتحقق أن لا أثر للقديم بقي.

## تحذيرات تقنية دقيقة

| التحذير | السبب |
|---|---|
| لا تُضف `default null::text` لتوقيع `lookup_card`/`self_service_card` | يكسر إعادة الترحيل: `cannot remove parameter defaults` |
| `START-RECOVERY.bat` يجب أن يبقى CRLF | `.gitattributes` يفرضه؛ LF يعطي «was unexpected at this time» |
| لا تستعمل منفذاً ثابتاً في اختبارات الخادم | خادم يتيم يمنع كل الفحوص برسالة مضلّلة |
| لا تعتمد على أعداد ثابتة في الاختبارات | اشتقها — الأعداد تتغير |
| احترم `KNOWN_GAPS` في `tools/recovery-core.mjs` | ٦ استثناءات معلنة، ليست نقصاً |
| لا تقنيع، ولا `profileLocked=true` | قرار المالك؛ آخر ترحيل إنتاجي اسمه `card_lookup_guard_no_masking` |
| `PGlite` يثبت SQL لا خدمات Supabase | لا تُعمّم النتيجة على Auth/Storage |
