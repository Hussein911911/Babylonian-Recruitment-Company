# استعادة الموقع من الصفر — دليل عربي

> **لمن هذا الدليل؟** لشخص يعيد تشغيل موقع شركة الهدف للتوظيف إن فُقد مشروع
> Supabase أو تعطّل الموقع. لا يفترض خبرة تقنية عميقة، ويقلّل الطرفية إلى أدنى
> حدّ ممكن — **لكن لا يزيلها تماماً**، لأن بعض الخطوات تحتاجها فعلاً.

**الوقت المتوقع:** ٤٥–٩٠ دقيقة.
**ما تحتاجه:** جهاز فيه متصفح، ملف `rescue-kit.zip`، ملف `HRC-FULL-*.sql`،
صور التخزين.

---

## المرحلة ٠ — فهم الخريطة

الموقع مركّب من **أربع قطع منفصلة**. فقدان قطعة لا يعني فقدان الباقي:

| القطعة | أين تعيش | هل تُفقد لو حُذف Supabase؟ |
|---|---|---|
| الكود | GitHub + Cloudflare | لا |
| القاعدة (بياناتك) | Supabase | **نعم — هذه الخطر الحقيقي** |
| الملفات (صور) | Supabase Storage | **نعم** |
| الحسابات | Supabase Auth | **نعم** |

## المرحلة ١ — مشروع Supabase جديد

1. افتح `supabase.com` ← سجّل دخول (أو أنشئ حساباً جديداً).
2. `New project`:
   - **Name:** `hrc` (أي اسم)
   - **Region:** `Frankfurt (eu-central-1)` — نفس المنطقة القديمة
   - **Database Password:** كلمة قوية — **احفظها في مكان آمن الآن**
3. انتظر حتى تصبح الحالة `Active` (دقيقة–دقيقتان).
4. اكتب **Project Ref** (يظهر في `Settings → General` أو في الرابط).

### ١.١ فعّل الامتدادات

`Database → Extensions` ← فعّل:

- ✅ `pgcrypto`
- ✅ `pg_cron`

> بدون `pgcrypto` يفشل الاسترجاع فوراً برسالة عن `gen_random_bytes`.

### ١.٢ أعلن السكيما

`Project Settings → API → Exposed schemas` ← أضف:

```
brc
```

> **هذه أشهر خطوة تُنسى.** بدونها يفتح الموقع فارغاً تماماً رغم أن القاعدة مليئة.

## المرحلة ٢ — استرجاع القاعدة

عندك طريقتان. **الطريقة (أ) هي الموصى بها** لأنها تتحقق من كل شيء.

### الطريقة (أ) — أداة الاسترجاع بضغطة

1. افتح مجلد `recovery-tools/` من الحزمة.
2. انقر نقراً مزدوجاً على `recovery/START-RECOVERY.bat`.
3. المتصفح يفتح تلقائياً على صفحة عربية.
4. **اسحب** ملف `HRC-FULL-*.sql` إلى المربّع الأول.
5. من لوحة Supabase: `Connect` ← تبويب **Direct connection** ← انسخ الرابط،
   واستبدل `[YOUR-PASSWORD]` بكلمة المرور.
6. اضغط **«افحص القاعدة الهدف أولاً»** — يجب أن يقول «مشروع صحيح، وفارغ».
7. اضغط **«جرّب على قاعدة داخلية»** — ينفّذ الملف على قاعدة وهمية. إن ظهرت
   أعدادك، الملف سليم.
8. اكتب كلمة **استرجع** في حقل التأكيد ← اضغط الزر الأحمر.
9. انتظر. **لا تُغلق النافذة السوداء.**
10. ستظهر لك جداول الأعداد + تقرير مطابقة. طابقها مع `INVENTORY.json.md`.

> **أول تشغيل يحتاج إنترنت** لتثبيت الأدوات (مرة واحدة). بعدها يعمل بلا إنترنت.
> **إن ظهر خطأ في النافذة السوداء:** انسخ آخر سطرين منه.

### الطريقة (ب) — سطر أوامر واحد

إن كانت الأداة لا تعمل:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f HRC-FULL-2026-11-18.sql
```

`DATABASE_URL` من نفس مكان الخطوة ٥.

## المرحلة ٣ — بعد الاسترجاع مباشرة

### ٣.١ المهام المجدولة

نفّذ `config/recreate-cron.sql` في `SQL Editor` باللوحة.

> بدونه: لا إفراج تلقائي عن الحجوزات، ولا أرشفة، ولا نسخة ليلية. القاعدة تعمل
> لكن بلا أتمتة.

### ٣.٢ الصور

1. `Storage → New bucket` ← الاسم **بالضبط**: `job-images` ← ✅ **Public**
2. ارفع الملفات من `storage/job-images/` بنفس المسارات (`jobs/...`).
3. أو نفّذ `config/storage-restore.sql` ثم ارفع الملفات.

### ٣.٣ تحقّق سريع

في `SQL Editor`:

```sql
select 'applicants' t, count(*) from brc.applicants
union all select 'jobs', count(*) from brc.jobs
union all select 'job_attempts', count(*) from brc.job_attempts
union all select 'staff', count(*) from brc.staff;
```

طابقها مع الأعداد في `INVENTORY.json.md` §٣.

## المرحلة ٤ — الحسابات

### إن استُورد `auth.users` (الأفضل)

كلمات المرور القديمة **تعمل كما هي**. لا تفعل شيئاً.

### إن لم يُستورد

1. `Authentication → Users → Add user` ← أنشئ الحسابات الثلاثة ببريد جديد.
2. `Authentication → URL Configuration` ← **Site URL** = نطاقك.
3. ادخل الموقع بحساب مدير، واذهب `الإعدادات → إضافة موظف` لربطهم بـ`brc.staff`.

> ⚠️ الحساب لا يعمل حتى يوجد له صف في `brc.staff` بدور صحيح.
> ⚠️ سياسة `rate_limit_email_sent = 2/ساعة` قد تعطّلك — انتظر أو ارفعها مؤقتاً.

## المرحلة ٥ — ربط الموقع بالمشروع الجديد

المعرّف القديم مكتوب في **٥ أماكن**، ليس مكاناً واحداً. تعديل الأول وحده يعطي
موقعاً يفتح ولا يتصل — وهذا أسوأ من عدم العمل لأنه يبدو نجاحاً.

من مجلد الكود:

```bash
node tools/supabase-repoint.mjs <المعرّف-الجديد> <المفتاح-العام-الجديد>
```

المفتاح العام من `Project Settings → API → anon/publishable`.

ثم:

```bash
git add -A && git commit -m "repoint to new supabase project" && git push
```

## المرحلة ٦ — النشر على Cloudflare Pages

### إن بقي المشروع القديم

كل شيء يبقى كما هو — الدفع إلى `main` ينشر تلقائياً.

### إن احتجت مشروع Cloudflare جديداً

1. `dash.cloudflare.com` ← `Workers & Pages` ← `Create` ← `Pages` ← `Connect to Git`.
2. اختر المستودع ← **Production branch: `main`**.
3. **Build command:** اتركه **فارغاً**
4. **Build output directory:** `dist`
5. `Save and Deploy`.

> ⚠️ إن تركت مخرجات البناء `.` بدل `dist`، سينشر مجلد الكود الخام —
> بما فيه `tests/` و`tools/`. لا تفعل.

**الدومين المخصص:** حالياً لا يوجد (`hrc-babil.com` غير مسجَّل). الموقع يعمل على
`*.pages.dev`. **لا تطبع استمارات على نطاق قبل تسجيله وربطه فعلاً** — وإلا صار
رمز QR المطبوع رابطاً ميتاً.

## المرحلة ٧ — فحوص النجاح

افتح الموقع واختبر بهذا الترتيب:

| # | الاختبار | المتوقع |
|---|---|---|
| 1 | الصفحة الرئيسية | تُحمّل، تُظهر الوظائف |
| 2 | عدد الوظائف | ٢٢ (أو عددك الحقيقي) |
| 3 | صورة وظيفة | تظهر (لا رمز مكسور) |
| 4 | دخول بحساب موظف | ينجح |
| 5 | `لوحة التحكم` | تُظهر أعداداً صحيحة |
| 6 | بحث بباركود بطاقة | يجد العميل |
| 7 | صفحة التحقق `verify.html` | تعمل |
| 8 | إضافة عميل تجريبي | تُحفظ |
| 9 | **حذف العميل التجريبي** | — |

**إن فشل #1 أو #2:** السكيما `brc` غير معلنة، أو المفتاح لم يُحدَّث.
**إن فشل #3:** الصور لم تُرفع، أو المخزن ليس Public.
**إن فشل #4:** `auth.users` لم يُستورد، أو الحساب بلا صف في `brc.staff`.

## المرحلة ٨ — النسخ الاحتياطي من جديد

**فوراً بعد نجاح كل ما سبق:**

1. ادخل الموقع بحساب مدير ← `restore.html` (أو صفحة النسخ).
2. نزّل نسخة كاملة جديدة.
3. احفظها في **مكانين**: الفلاش + قرص خارجي.
4. افتح الأداة واختبر الملف الجديد بـ«جرّب على قاعدة داخلية».

> النسخة القديمة صارت قديمة. النسخة التي لم تُجرَّب ليست نسخة.

## ما لا يمكن استرجاعه إطلاقاً

| الشي | لماذا |
|---|---|
| الجلسات المفتوحة | تنتهي حتماً بعد النقل |
| سجلات Storage المرفوعة بعد آخر نسخة | لم تكن في النسخة |
| أي تغيير بعد تاريخ النسخة | نفس السبب |
| إعدادات المشروع (الامتدادات، السكيما المعلنة، Auth) | تُعاد يدوياً — موثّقة في `config/` |

**القاعدة:** أي شيء لم يكن داخل ملف النسخة لحظة أخذها، **لا يعود**.

## إن تعطّل شيء

| الرسالة | المعنى | الحل |
|---|---|---|
| `function gen_random_bytes does not exist` | `pgcrypto` غير مفعّل | فعّله من Extensions |
| `permission denied for schema brc` | السكيما غير معلنة | أضف `brc` في Exposed schemas |
| `relation "brc.applicants" does not exist` | الاسترجاع لم يصل | أعد تشغيل الأداة |
| الأداة تقول «القاعدة فيها بيانات» | ليست فارغة | **توقّف** — قد تكون قاعدتك الحالية |
| موقع يفتح فارغاً | السكيما أو المفتاح | راجع المرحلة ١.٢ و٥ |
| صور مكسورة | المخزن خاص أو ناقص | راجع المرحلة ٣.٢ |
| «رابط التأكيد لا يفتح» | `site_url` = localhost | راجع المرحلة ٤ |
