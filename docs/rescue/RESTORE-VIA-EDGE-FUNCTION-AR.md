# الاسترجاع من داخل Supabase نفسه — بلا تثبيت أي شيء على أي حاسوب

> **الطريق الثاني.** لا Node، لا psql، لا كلمة مرور قاعدة، لا حاسوب أصلاً:
> كل الخطوات من متصفّح، وداخل لوحة Supabase وحدها.
>
> الملف: `supabase/functions/hrc-restore/index.ts` ·
> الاختبار: `npm run test:restore-edge` (36 فحصاً)

---

## ١) الفكرة في سطر واحد

Supabase يضخّ في بيئة كل دالة سحابية رابطَ قاعدته (`SUPABASE_DB_URL`) تلقائياً.
فأنشر دالةً صغيرة **داخل المشروع نفسه**، وهي التي تقرأ ملف النسخة الاحتياطية من
Storage وتنفّذه على القاعدة وتقارن الأعداد. أنت تفتح رابطاً في المتصفّح، فترى
`PASS` أو رسالة عربية تقول ما الذي منع التنفيذ.

```
  أنت (المتصفّح)
     │  GET https://<REF>.supabase.co/functions/v1/hrc-restore?key=…&confirm=RESTORE
     ▼
  Edge Function «hrc-restore»  ──►  Storage: restore-tmp/HRC-FULL-….sql
     │                                    (تقرأ الملف)
     └──►  قاعدة المشروع عبر SUPABASE_DB_URL (‏متغيّر بيئي يضخّه Supabase)
              │
              └──► تحقّق: كل جدول مقابل أعداد ترويسة الملف ⇒ PASS / FAIL
```

---

## ٢) ما تحتاجه قبل البدء

| الشيء | من أين |
|---|---|
| مشروع Supabase **جديد وذرّي** | supabase.com → New project (احفظ كلمة المرور في مدير كلمات المرور) |
| ملف `HRC-FULL-<التاريخ>.sql` | صفحة النسخ الاحتياطي في موقعك (`backup` → تنزيل الملف الكامل) |
| رمز تشغيل تختاره أنت | ٢٠ حرفاً أو أكثر، تحفظه في مدير كلمات المرور — لا يُكتب في أي محادثة |

⚠️ **المشروع الجديد فقط.** `hrc-restore` ترفض العمل على مشروع الإنتاج
`vqsvztudvfukyuerzcgx` بالاسم (‏403) مهما كان الرمز صحيحاً.

---

## ٣) الخطوات — سبع خطوات، كلها بالنقر

### الخطوة ١ — ارفع الملف إلى Storage

1. في لوحة المشروع الجديد: **Storage** → **New bucket**.
2. الاسم بالحرف: `restore-tmp` — وأبقِ **Public** مطفأً (خاص).
3. افتح الوعاء → **Upload file** → اختر `HRC-FULL-<التاريخ>.sql`
   (حجمه ~٣٫٧ م.ب — تحت كل حدود الرفع).

> لا ترفعه داخل مجلّد فرعي، ولا تغيّر امتداده. الدالة تجد الملف `.sql` الوحيد
> في الوعاء تلقائياً، وإن وجدت أكثر من واحد طلبت منك تحديده.

### الخطوة ٢ — انشر الدالة

1. **Edge Functions** → **Deploy a new function**.
2. الاسم بالحرف: `hrc-restore` (بحرف n صغير، وشرطة واحدة).
3. اختر **Via Editor** (لا Via CLI) — يُفتح محرّر كود في المتصفّح.
4. افتح الملف `supabase/functions/hrc-restore/index.ts` من المستودع، وانسخ
   **كل** محتواه (من أول سطر إلى آخر سطر) والصقه في المحرّر مكان المحتوى الافتراضي.
5. 🔴 **أطفئ مفتاح `Verify JWT`** قبل النشر. الحماية هنا بالرمز السري
   (`RESTORE_TOKEN`) لا بجلسة مستخدم؛ ولو بقي المفتاح مفعّلاً لرُفض كل طلب.
6. **Deploy** وانتظر حتى تصبح الحالة `ACTIVE`.

### الخطوة ٣ — اضبط رمز التشغيل

1. **Project Settings** → **Edge Functions** → **Secrets**
   (أو من صفحة الدالة: تبويب **Secrets**).
2. **Add new secret**: الاسم `RESTORE_TOKEN` — القيمة رمز طويل تختاره أنت
   (٢٠ حرفاً أو أكثر، حروفاً وأرقاماً).
3. احفظه في مدير كلمات المرور. **بلا هذا السرّ ترفض الدالة العمل** (‏500)
   حتى لو كان كل شيء آخر صحيحاً — وهذا مقصود.

### الخطوة ٤ — التجربة الجافّة (لا تكتب شيئاً)

افتح في المتصفّح (بدّل `<REF>` إلى معرّف مشروعك، وهو الجزء الأول من رابط المشروع):

```
https://<REF>.supabase.co/functions/v1/hrc-restore?key=<RESTORE_TOKEN>&dry=1
```

الردّ المتوقّع:

```json
{
  "ok": true,
  "mode": "dry-run",
  "verdict": "READY",
  "file": "HRC-FULL-2026-11-21.sql",
  "bytes": 3864629,
  "sha256": "d47c5085…93aed8",
  "statements": 403,
  "willRun": { "expected": { "applicants": 726, "jobs": 22, "…": 0 } },
  "current": { "tables": { "applicants": 0 }, "secret": "missing" },
  "next": ["افتح الرابط نفسه بلا dry=1 وأضف &confirm=RESTORE …"]
}
```

هذه الخطوة تثبت أربعة أشياء قبل أي كتابة: الرمز صحيح · الملف وصل ·
الملف يُقرأ ويُقسَّم إلى ٤٠٣ عبارة · القاعدة مقروءة.
**راجع `sha256`** هنا مقابل البصمة المحفوظة عندك.

### الخطوة ٥ — الاسترجاع الحقيقي

```
https://<REF>.supabase.co/functions/v1/hrc-restore?key=<RESTORE_TOKEN>&confirm=RESTORE
```

- `confirm=RESTORE` إلزامي — بدونه لا تُنفَّذ أي عبارة (حماية من فتح الرابط سهواً).
- إن كانت القاعدة **غير فارغة** يرفض ويُخبرك بعدد المتقدّمين، ولا يمضي إلا
  بإضافة `&force=YES`.
- المدة المتوقّعة: ثوانٍ (المقاس محلياً: **٠٫٨ ثانية** لـ٤٠٣ عبارة).

الردّ المتوقّع — وهذا هو «الإيصال»:

```json
{
  "ok": true, "verdict": "PASS", "seconds": 4.2, "executed": 403,
  "file": "HRC-FULL-2026-11-21.sql", "sha256": "d47c5085…",
  "checks": [
    { "name": "applicants",  "expected": 726, "actual": 726, "ok": true },
    { "name": "audit_log",   "expected": 3814, "actual": 3814, "ok": true },
    { "name": "counter",     "expected": 176, "actual": 176, "ok": true },
    { "name": "disabled_triggers", "expected": 0, "actual": 0, "ok": true }
  ],
  "appSecret": { "state": "missing", "verifyTokenLength": null, "ok": false },
  "next": ["مفتاح البصمة غير مضبوط: …", "أضف brc إلى Exposed schemas …"]
}
```

`verdict: "PASS"` يعني: **كل جدول يطابق عددَه المكتوب في ترويسة الملف**، ولا
مشغّل واحد بقي معطّلاً. وإن اختلف أي عدد فـ`verdict: "FAIL"` مع قائمة
`failedChecks`، والردّ يشرح العبارة التي توقّف عندها التنفيذ ورقمها ونصّها.

### الخطوة ٦ — مفتاح البصمة (`brc_secret`)

بعد الاسترجاع يُفرَّغ جدول `brc.app_secrets` (لأن الملف يبدأ بـTRUNCATE)، فتفشل
`brc.verify_token` — أي أن بطاقة مطبوعة سابقاً لن تُتحقّق. ولذلك `appSecret.state`
يكون `missing`. أمامك طريقان:

**أ) سطر واحد في محرّر SQL** (الأبسط، والملف قصير فلا يُبتر):

```sql
insert into brc.app_secrets (name, value) values ('brc_secret', '<القيمة>')
on conflict (name) do update set value = excluded.value, updated_at = now();
select length(brc.verify_token('HRC-BC-000120'));   -- يجب أن يكون 64
```

**ب) عبر الدالة نفسها بطلب POST** — لا يمرّ الرمز في رابط ولا في سجلّ:

```bash
curl -X POST "https://<REF>.supabase.co/functions/v1/hrc-restore" \
  -H "Content-Type: application/json" \
  -d '{"key":"<RESTORE_TOKEN>","confirm":"RESTORE","force":"YES","reset":"YES","brcSecret":"<القيمة>"}'
```

أو من محرّر الاختبار في لوحة الدالة (تبويب **Invoke / Test**) بالجسم نفسه.
الردّ حينها: `"appSecret": { "state": "set-now", "verifyTokenLength": 64, "ok": true }`.
وللدالة تحقّق شكلي: تقبل ١٦–٢٠٠ حرفاً من `A-Za-z0-9+/=_-` فقط.

> القيمة نفسها موجودة في `config/brc_secret.enc` داخل حزمة الطوارئ (مشفّرة
> بكلمة مرورك)، أو في مدير كلمات المرور عندك. **لا تُرسلها في أي محادثة.**

### الخطوة ٧ — بقية الإعدادات (خارج نطاق الدالة)

| ما تبقّى | من أين |
|---|---|
| `brc` في **Exposed schemas** | Project Settings → API → Exposed schemas |
| `site_url` و`uri_allow_list` | Authentication → URL Configuration (القيم في `docs/rescue/auth-settings.md`) |
| مهام `pg_cron` الأربع | نفّذ `docs/rescue/recreate-cron.sql` في محرّر SQL |
| الحسابات الثلاثة + ربط `auth_id` | `config/accounts.json` ثم `update brc.staff …` |
| وعاء الصور `job-images` | `docs/rescue/storage-restore.sql` (والصور خارج نطاق هذه الحزمة) |
| الموقع نفسه | `node tools/supabase-repoint.mjs <REF> <KEY>` ثم `npm run dist` (يحتاج حاسوباً) |

### الخطوة ٨ — نظِّف بعدك (مهم)

بعد أن تطمئن أن كل شيء يعمل:

1. **احذف الدالة `hrc-restore`** (Edge Functions → … → Delete).
2. **احذف الوعاء `restore-tmp`** بما فيه ملف البيانات (فيه بيانات ٧٢٦ شخصاً).
3. **احذف السرّ `RESTORE_TOKEN`**.

الدالة خامدة بلا سرّها، لكن لا معنى لترك بابٍ مغلق بمفتاح موجود.

## ٤) ماذا تعني كل رسالة خطأ

| الحالة | المعنى | الحل |
|---|---|---|
| `500` «السرّ RESTORE_TOKEN غير مضبوط» | الخطوة ٣ لم تُنفَّذ | أضف السرّ |
| `401` «مفتاح التشغيل غير صحيح أو غائب» | `key=` خطأ أو ناقص | انسخ الرمز من Secrets حرفياً |
| `403` «ترفض العمل على مشروع الإنتاج» | أنت على مشروع الإنتاج | توقّف — هذا مقصود |
| `400` «الوعاء لا يحوي أي ملف .sql» | الملف في مجلّد فرعي أو بامتداد آخر | ارفعه في جذر الوعاء بامتداد `.sql` |
| `400` «الوعاء يحوي ٣ ملفات .sql» | نسخ قديمة متراكمة | أضف `&file=<الاسم>` أو احذف القديم |
| `400` «الملف نسخة قديمة تستعمل TRIGGER ALL» | نُزّل قبل 2026‑11‑20 | نزّل نسخة جديدة من صفحة النسخ الاحتياطي |
| `409` «القاعدة ليست فارغة — فيها ٧٢٦ متقدماً» | حماية من المحو | إن كان مقصوداً: `&force=YES` |
| `500` عند العبارة ٦٦ «cannot drop columns from view» | مخطط `brc` موجود بشكل مختلف | `&force=YES&reset=YES` (يمحو `brc` ويبنيه من الصفر) |
| `500` «تجاوزنا مهلة الدالة» | الخطة المجانية تسمح بـ١٥٠ ثانية | أعد المحاولة، أو استعمل طريق Colab |
| عدد لا يطابق (`FAIL`) | الاسترجاع لم يكتمل أو الملف ناقص | لا تعتمد النسخة — أعد التنفيذ واقرأ `failedChecks` |

**عن `reset=YES`:** الملف يفترض قاعدة نظيفة. إعادة تنفيذه على مخطط موجود
تُفشل المرحلة ١ في PostgreSQL نفسه (‏`create or replace view` لا يغيّر الأعمدة)،
وليس في هذه الدالة. لذلك صار `reset=YES` موجوداً: يمحو مخطط `brc` كاملاً ثم
يبني من الصفر — وهو أيضاً الطريق لتحديث نسخة قائمة بملف أحدث.
لا يُقبل `reset` بلا `force`، ولا يُقبل `force` بلا `confirm=RESTORE`.

## ٥) الأمان — ما يجعله مقبولاً

| الخطر | الحماية |
|---|---|
| عابر يفتح الرابط | `RESTORE_TOKEN` إلزامي، مقارنة بزمن ثابت |
| فتح الرابط بالخطأ يمحو البيانات | `confirm=RESTORE` + حاجز «القاعدة غير فارغة» (`force`) |
| تنفيذ على الإنتاج | حاجز اسم المشروع (403) — قبل أي اتصال بالقاعدة |
| ملف خاطئ | فحص شكل الملف، ورفض نسخ `TRIGGER ALL` القديمة |
| تسريب السرّ في السجلّات | `brcSecret` يُقبل في جسم POST فقط، ولا يُطبع في أي ردّ أو رسالة |
| نسيان الباب مفتوحاً | رمز قصير العمر: بعد الانتهاء احذف الدالة والوعاء والسرّ (الخطوة ٨) |

ما **لا** تحميه الدالة: من يملك حساب المالك على المشروع يستطيع كل شيء أصلاً.
ولو تسرّب `RESTORE_TOKEN` فأسوأ ما يفعله هو استرجاع نسخة **أنت** رفعتها —
لا قراءة بيانات ولا تصديرها.

> **لماذا لا تُستعمل الحزمة المشفّرة `.hrcbak` هنا؟** لأن فكّها يحتاج scrypt،
> وتمرير كلمة مرور الحزمة في رابط أو جسم طلب إلى خدمة خارجية مرفوض. الملف
> الخام `.sql` يأتي من صفحة النسخ الاحتياطي نفسها. أما `.hrcbak` فمكانها
> النسخة المحفوظة على قرص/USB، أو طريق Node.

## ٦) ما لم يُختبر — بصراحة

| البند | الحالة |
|---|---|
| التشغيل داخل بيئة Deno الحقيقية | ❌ لم يُجرَّب (لا شبكة لهذا الصندوق إلى `*.supabase.co`) |
| الاتصال بـSupavisor (الـpooler) من دالة | ❌ لم يُجرَّب — نستعمل `prepare: false` وهي إعدادته الموصى بها |
| تنزيل الملف من Storage عبر HTTP | ⚠️ حُوكي في الاختبار بردٍّ يشبه Storage تماماً، لا على Storage حقيقي |
| تقسيم الملف وتنفيذه | ✅ مُثبَت: ٤٠٣ عبارة على PostgreSQL 17 بلا خطأ، وكل الأعداد مطابقة |
| الحراسات (رمز/إنتاج/confirm/force/reset/ملفات خاطئة) | ✅ ٢٠ فحصاً في `tests/restore-edge-function.mjs` |
| المهلة الزمنية على الخطة المجانية | ⚠️ المقاس المحلي ٠٫٨ ثانية؛ هامش كبير لكنه غير مضمون على الشبكة |

إن فشل شيء في البيئة الحقيقية فالرسالة عربية وتقول العبارة ورقمها — أرسل لي
نصّها كما هو، لا صورة، وأنا أعالجها.

**الفرق عن الطريقين الآخرين:** `docs/rescue/STANDBY-AR.md` (Node/psql — كل شيء
محلي، مُختبَر أكثر)، وطريق Google Colab (‏Python في المتصفّح، ينفّذ الملف
باستعلام واحد، يحتاج حساب Google فقط).
