## 2) 🔴 الباب الخلفي — المشكلة الحرجة

### ما يجري بالضبط

`assets/js/supabase-config.js` يحمل `enforceAuth: false`، و`assets/js/config.js`
يحمل حساباً مكتوباً بالكود:

```js
// assets/js/config.js:59
users: [
  { username: 'admin', password: 'admin123', name: 'المدير العام', role: 'admin', title: 'مدير عام', active: true }
],
```

وهذان معاً — بعد فشل الدخول عبر Supabase Auth — يجعلان `dashboard.js` يجرّب
الدخول المحلي (`dashboard.js:612` ← `store.js:344`)، فيدخل **أي شخص** يكتب
`admin / admin123` إلى المنظومة الداخلية **بصلاحية مدير عام**، بلا حساب ولا جلسة.

### الإثبات (تشغيل فعلي على الصفحة المنشورة)

فحص مستقل يفتح `dashboard.html` كما هي (بلا أي تزييف للإعداد ولا زرع حسابات
اختبارية)، مع عميل قاعدة يحاكي رفض Supabase Auth لكل بيانات الدخول:

```
$ node tests/.tmp/review-backdoor.mjs
الإعداد المنشور — enforceAuth = false
حسابات مكتوبة في config.js = ["admin/admin123"]
حالة السحابة: degraded | الدور: guest

——— النتيجة ———
لوحة المنظومة ما زالت مخفية؟ false
الجلسة الحالية: admin / admin

🚨 الباب مفتوح: زائر غريب دخل بصلاحية «admin».
```

الحساب موجود أيضاً داخل الملفّين المنشورين القابلين للتنزيل:

### حجم الضرر — ما يناله الدخيل وما لا يناله

**يناله:**
- **دخول كامل إلى المنظومة الداخلية بصلاحية «مدير عام»** — كل الشاشات: الوظائف,
  البطاقات, الاستمارات, الحجوزات, الإعدادات, سجل التدقيق (شكلياً).
- إمكانية إصدار استمارات وبطاقات **محلياً** في متصفحه (بأرقام تسلسلية قد تتصادم
  مع أرقام الشركة الحقيقية)، وطباعتها بمظهر رسمي.

**لا يناله (بفضل تصميم جيّد قائم):**
- **بيانات الشركة الحقيقية لا تُقرأ ولا تُكتب** من جلسة محلية: الكتابة والقراءة
  السحابية مقصورتان على `cloud.role === 'staff'` (جلسة موظف حقيقية)، والدور يبقى
  `guest` في الدخول المحلي (`store.js:370` — يفصل الجلسة السحابية عمداً).
- سياسات RLS في القاعدة تسحب كل الصلاحيات من `anon` على الجداول الستة
  (`revoke all ... from anon` في مخطط القاعدة) — فالمفتاح العام وحده لا يكفي.

**لكن الخطر يبقى قائماً:** أي زائر يعرف العنوان يحصل على واجهة المنظومة الإدارية
ويظهر له «مدير عام»، وأي خلل مستقبلي في RLS يصبح اختراقاً فعلياً لا مجرد دخول
شكلي. وهذا وحده يخالف البند الأول في قائمة التسليم الخاص بك.

## 2ب) ⚙️ إدارة حسابات الموظفين — مراجعة وإصلاح (2026-10-13)

بطلب من المالك: «راجع موضوع إنشاء الحسابات لدى المدير وأريده فعّالاً». روجعت
السلسلة كاملة من الزر في اللوحة حتى سطر `brc.staff` في القاعدة، ثم نُفِّذ ما يلي.

### ما كان يعطّل التجربة

| # | العلّة | الأثر على المدير |
|---|---|---|
| 1 | الدالة السحابية `hrc-staff-admin` **موجودة في المستودع وغير مُعلَنة** في `supabase/config.toml` | لا تُنشر أبداً مع الدفعات (تكاملة GitHub لا تنشر إلا المُعلَن) ⇒ كل محاولة إنشاء تصل إلى «الدالة غير منشورة» |
| 2 | إن لم توجد قناة (لا دالة ولا مفتاح) كان الحساب **يُنشأ محلياً** مع تنبيه صغير | الموظف «مُضاف» في نظر المدير ولا يدخل من أي جهاز |
| 3 | انقطاع الشبكة كان يعطي رسالة المكتبة الإنجليزية `Failed to send a request to the Edge Function` | نص إنجليزي غامض في نموذج الموظف، وبلا أي محاولة للمسار الاحتياطي |
| 4 | مفتاح الخدمة يُحفظ **بلا فحص** | خطأ المفتاح لا يظهر إلا عند أول إنشاء حساب، وبرسالة لا تُسمّي السبب |
| 5 | لا شيء يقول للمدير **قبل** فتح النموذج: هل ستُسجَّل الحسابات في القاعدة أم لا؟ | يكتشف الأمر في نهاية الطريق |

### ما نُفِّذ

1. **إعلان الدالة في `supabase/config.toml`** (`[functions.hrc-staff-admin] enabled = true, verify_jwt = true`)
   ⇒ صار نشرها تلقائياً مع كل دفع/دمج إلى `main` (توثيق Supabase: الدوال المُعلَنة في
   `config.toml` تُنشر مع «Deploy to production»). هذا وحده يقلب المسار من «معطّل» إلى «يعمل».
2. **شريط «قناة إنشاء الحسابات»** أعلى جدول الموظفين: ثلاث قنوات (جلسة القاعدة ·
   الدالة السحابية · مفتاح الخدمة) + حكم نهائي بالعربي + زر **«فحص القناة»** ينداء
   الدالة بإجراء `whoami` التشخيصي (لا يُنشئ ولا يعدّل)، + زر «ما الذي ينقص؟».
3. **لا إنشاء محلي صامت**: نافذة «لا قناة لإنشاء الحسابات بعد» تعرض الخطوات الثلاث
   (نشر الدالة · إضافة المفتاح فوراً · إنشاء محلي صريح بتحذيره)، ونموذج الموظف يبقى
   مفتوحاً ليعيد المحاولة بعد إضافة المفتاح.
4. **فحص مفتاح الخدمة قبل حفظه**: قراءة سطر من `brc.staff` بالمفتاح، مع تمييز
   ثلاث حالات مختلفة العلاج (مفتاح مرفوض · سكيما `brc` غير مكشوفة · لا اتصال)،
   وخيار «احفظ رغم ذلك» لمن يعرف أن السبب مؤقّت.
5. **انقطاع الشبكة**: `code = 'network'` + جملة عربية، ويُجرَّب المفتاح المحفوظ
   بدل إسقاط الطلب (كان `sessionGap` يستثني الشبكة فيسقط بلا محاولة).

## 3) ⚠️ مجلد النشر `npm run dist`

```
✗ مراجع ناقصة في مجلد النشر (1):
  • apply.html → db-update.html
```

  `tools/dist.mjs`، فالمسار يصير ميتاً في أي نشر من `dist/`.

  الـ404 بهوية الشركة (يظهر رد Cloudflare الافتراضي). النشر من جذر Git لا يتأثر.

> الأثر محدود لأن الوثائق تقول إن `dist/` للنشر اليدوي الاستثنائي وأن النشر
> المعتمد ينشر الجذر كاملاً — لكن الفحص يفشل، وهذا يعني «موقع منشور بأصل ناقص»
